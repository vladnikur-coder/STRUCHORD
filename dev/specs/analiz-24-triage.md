## Что предлагается по бэкапам (ждёт решения владельца)

1. **Главный архив уже есть — Git.** В папке проекта лежат все прошлые версии (`.git` 73 МБ), а `push` на GitHub — это и есть копия «в другом месте». Правило: после каждой сданной волны — `push`.
2. **На компьютере держать не всё, а релизы.** Последние 10 ручных копий + файлы, отмеченные как релиз. Имя копии — с версией: `STRUCHORD-0.703.html`; тогда и без папок понятно, что внутри.
3. **Помеченные релизы сейчас никак не помечены:** в репозитории 0 тегов. Предложение — ставить тег на сданную волну (`git tag v0.703 && git push origin v0.703`). Это дешевле, чем папка копий, и версию всегда видно в списке.
4. **Проверка копии — 5 секунд:** открыть её двойным кликом и посмотреть номер версии в шапке (`· ver 0.703`).
5. **Не хранить 700 копий:** 700 × 5,9 МБ ≈ 4 ГБ, в которых нужную всё равно не найти. Смысл имеет не количество копий, а то, что среди них есть каждая сданная версия.
