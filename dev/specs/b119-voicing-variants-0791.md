# B-119 · 0.791 — варианты расположения: единый список + карточки в панели

Дата: 2026-11-04. Ветка: `arena/bf99fe44-struchord`. Версия: 0.791 (`ver 0.791` + `struchord-v791` парой, R7).

## Контекст и опрос R8

Кирпич 5 очереди B-39, требование 1 из `dev/specs/piano-voicing-review.md`:
«предлагать несколько осмысленных вариантов, а не выдавать один за
профессиональную аранжировку». R8 (2026-11-04), резюме подтверждено `final=yes`:

- **UI:** карточки вариантов у текущего аккорда в панели клавишных
  (миниклавиатура + подпись), клик выбирает; кнопки ± остаются.
- **Набор:** база `generateKeysVoicings`/`inversionCandidates` + «широкие»
  варианты (октавное удвоение верхней ноты правой руки) — только при
  `range.size >= 61` и если нота влезает в диапазон и в `handLimit`.
- **Защита:** ручной выбор (карточка/±) и `exactNotes` побеждают; старые
  песни без галочки `linkedVoicings` — прежнее поведение; авто-выбор
  (голосоведение 0.790) ручной выбор не перетирает.
- **Формат:** полный комплект сразу, версия 0.791, read-only замер до кода.

## Read-only замер (до кода)

Ручной перебор уже существовал (± → `stepVariant` → `setVariantIndex` →
`voicings['v:'+chord]`), но нигде не показывался список вариантов — только
счётчик `N/M`. Каждый потребитель заново вызывал `generateKeysVoicings`:
панель (`renderPanel`), ± (`stepVariant`), `linkedSelection` (ручной
индекс), fallback за 2048, `setVoicingProvider` (звук при выключенном
gолосоведении), `selectedShape` и авто-модуль — потенциально разъехались бы
при изменении списка.

## Что изменилось

Патч `dev/tools/patch-b119-voicing-variants-0791.py` (17 якорей в `STRUCHORD.html`):

1. **`listVoicingVariants(chord,key,range,prev,opts)`** — единый список:
   база `generateKeysVoicings(...)` + в хвосте «широкие» (для первых двух
   базовых вариантов: RH top + 12, если `size>=61`, `base.length < handLimit`
   и `<= 9`, и нота ≤ `min(range.high, 84)`), без дублей по сигнатуре.
2. **`voicingLabel(notes,index,baseCount,f)`** — подпись: широким
   (index ≥ baseCount) — «Широкое · удвоение в октаву», иначе «Обращение»
   (бас ≠ корень) или по размаху RH: «Плотное» (≤12) / «Компактное» (≤17) /
   «Широкое».
3. Единый список подключён во все точки: `linkedSelection` (ручной индекс и
   fallback за 2048), `stepVariant`, `renderPanel`, `setVoicingProvider`,
   `selectedShape`, авто-модуль (с guard `|| generateKeysVoicings`).
   `inversionCandidates` (авто-голосоведение) остаётся на базе — авто не
   выбирает «широкие».
4. **UI:** `div#b39KeysVariants` под клавиатурой панели; в `renderPanel` при
   аккорде и >1 варианте — карточки `.b39-variant` (мини-SVG через
   `keyboardSVG` вокруг правой руки + подпись), активная подсвечена
   (`aria-pressed`), клик → `setVariantIndex(...)` + `renderPanel()`.
   CSS `.b39-keys-variants`/`.b39-variant` рядом с `.b39-keys-nav`.
5. R7: `ver 0.791` + `struchord-v791`.

## Совместимость

- Широкие добавлены **в конец** списка → ручные индексы, сохранённые до
  0.791, не сдвигаются; `linkedSelection` и звук разрешают индекс по тому же
  списку, что и UI.
- На 25/37/49 клавишах и когда рука не вмещает — список ровно прежний.
- `exactNotes` побеждает (счётчик «Своя», карточки не активны).
