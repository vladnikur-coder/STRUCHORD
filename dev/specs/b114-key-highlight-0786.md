## 2. Диагноз (замер до правки)

4/4 @120 BPM, ячейки по 2 с, аккорды **C → Am → F**, щелчки `t=2,000` и `t=4,000`:

| Момент | Что звучит | Что горело на панели |
|---|---|---|
| 1,00 — середина C | C: `48,55,60,64` | **`45`,55,60,64** — уже нота из Am |
| 2,05 — идёт изгиб | `48→45`, 55,60,64 | `45,53,57,60` — уже ноты из **F** |
| 2,30 — Am пришёл | Am: `45,55,60,64` | `45,53,57,60` — **F** |
| 3,00 — середина Am | Am | **F** |
| 4,05 — переход к F | `45`, `55→53`, `60→57`, 64 | **ничего** |
| Новая нота 67 | звучит с `t=2` | подсвечена с `t=0`, гаснет ровно в `t=2` |

**Причина.** `padGlide()` в момент планирования карты перехода ставит `v.midi = toMidi` — то есть помечает голос нотой **следующего** аккорда. Подсветка в `padStep()` читала именно `v.midi`:

```js
if (!v.dead) scheduleKeyHighlight(ctx, channel, v.midi, start, dur);
```

До 0.785 звук сам «подъезжал» к будущей ноте перед щелчком, поэтому в конце ячейки подсветка хотя бы совпадала с приближающимся звуком. 0.785 перенёс переход **на щелчок и после него** (`end = boundary + lead`): звук весь такт остаётся старым, а подсветка уже показывает следующий аккорд — расхождение стало равным целой ячейке. Три сопутствующих эффекта: `release`-голоса (`v.dead`) не подсвечивались вовсе; подсветка обрывалась ровно на границе, хотя звук живёт ещё `lead`; «новые» ноты загорались за такт до своего звучания.

**Важная оговорка:** во время изгиба звук находится *между* клавишами, поэтому «подсветка буквально равна звуку» невозможно — нужно дискретное правило. Владелец выбрал «по аккорду, смена на щелчке».

## 3. Что сделано

Одна правка по существу в `keyboard-audio.js::padStep()` (патч `dev/tools/patch-b114-key-highlight-0786.py`, 6 якорей / 3 файла):

- Заведён `litNotes`. В цикле по карте перехода, **до** вызова `padGlide()`, запоминается `p.from` — нота, которая реально звучит от `start` до щелчка. `new`-записи (`from === null`) сюда не попадают: они начинают звучать только после щелчка и подсвечиваются своей ячейкой.
- Подсветка планируется по `litNotes`, а не по `v.midi`:

```js
litNotes.forEach(function (m) {
  scheduleKeyHighlight(ctx, channel, m, start, dur);
});
```

- Интервал **сохранён** `[start, start + dur]`: записи следующей ячейки стартуют в её `start`, поэтому переключение происходит ровно на щелчке, пустоты на стыке нет. Уходящие ноты (`switch_clean`) горят до удара и гаснут на нём. Привязка к реально созданным голосам сохранена: `litNotes` пополняется только когда голос `v` найден/создан.
- В `padGlide()` добавлен комментарий-предупреждение, что `v.midi` теперь нота следующего аккорда и подсветка её не читает. Само голосоведение **не изменено**.
- R7: `STRUCHORD.html` → `ver 0.786` и `sw.js` → `struchord-v786` выложены парой.

**Не изменилось (принятый звук 0.785):** `boundary = start + dur`, `end = boundary + lead`, длина `lead = max(0,05; min(⅓ пульса; 0,35 с; 20 % ячейки))`, S-кривая из 33 точек по `playbackRate`, предел 7 полутонов, `hold` общих тонов, перетекание между секциями, мягкое гашение пустой ячейки/паузы/конца песни, `padNext` от плеера (0.783), часы метронома `metronomeGridKey` (0.784), `findNextEvent`, `previewEvent`, 0.775, мгновенный Стоп, `written` для MIDI/GPX/GP5, пианино/Rhodes/орган, миграции (нет). Очередь `keyHighlights`, фильтр по часам AudioContext и legacy-подсветка `playNote()` для не-pad тембров не переписаны.
