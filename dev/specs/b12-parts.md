## 2. Границы зонтика

**Зонтик B-12:** независимые дорожки внутри песни, общий файл и
воспроизведение, табовый редактор, микшер, приёмы, знаки структуры и
поэтапный импорт/экспорт GP/MIDI. Негитарная нота — абсолютная высота MIDI
`pitch` 0–127 (`C4 = 60`), не лад; обычная нотация и переключатель на неё
отложены до 12.10. На момент утверждения исходного объёма текущей была
итерация 12.9.2 — роли дорожек, раздельные табовый и pitch-домены, временный
ввод/звук; актуальный статус последующих итераций ведётся в §9.8–9.13.

**Не входит в 12.9.2:** импорт форматов, MIDI-автоподбор позиции,
нотный стан/пианоролл и качественные тембры/семплы. Эти границы остаются
на следующих итерациях; RSE Guitar Pro не используется. Печать/PDF (B-49)
остаётся откаченной и в кирпичи не возвращается без отдельной спеки.

**Не меняется:** текущий редактор аккордов, лента, круг, ритм-рулон,
аппликатуры. Партии живут параллельным режимом и связаны с песней общим
файлом и общим воспроизведением.

## 4. Модель данных (B-12.1)

`parts` содержит несколько дорожек. Два нотных домена живут отдельно и
никогда не пересчитываются один в другой при смене роли:

```json
"parts": [{
  "id": 1,
  "name": "Keys",
  "sourceName": "Imported Synth",
  "instrument": "keys",
  "gmProgram": 89,
  "midiChannel": 3,
  "tuning": "e-std",
  "visible": true,
  "rolls": { "1": [ { "start": 0, "dur": 1, "string": 5, "fret": 3 } ] },
  "pitchRolls": { "1": [ { "start": 0, "dur": 1, "pitch": 60, "line": 4,
                              "velocity": 90, "voice": 2 } ] }
}]
```

- `id` — целое, уникальное в песне; `name` — текст ≤ 60 символов;
  пустое имя превращается в «Партия N».
- `sourceName` — исходная подпись дорожки (если есть); редакторское
  переименование `name` её не затирает.
- `instrument` — `guitar`, `bass`, `drums`, `keys`, `vocal` или `other`;
  неизвестное значение безопасно читается как `guitar`.
- `gmProgram` — исходная программа 0–127, `midiChannel` — канал 1–16;
  поля необязательны и сохраняются только при корректных целых значениях.
- `tuning` задаёт временный табовый гриф. Для гитары/баса `null` означает
  строй песни; pitched-роли по умолчанию используют E2–A2–D3–G3–B3–E4.
  Строй и число струн (1–12) — подсказка для грифа, не транспозиция pitch.
- `rolls` — таб-домен по id секции: нота `{start, dur, string, fret}`.
  `string` — индекс от низкой струны, `fret` — 0–24. Неиграбельные линии
  не удаляются при смене роли; сериализатор временно записывает
  `rollStringLimit` (1–12) только если существующая нота выходит за текущий
  гриф. Санитайзер использует маркер при загрузке; в модели его не хранит.
  На текущем стане недостижимая нота показывается пунктиром и не звучит.
- `pitchRolls` — абсолютный MIDI-домен по id секции: обязательные
  `{start, dur, pitch}`; `pitch` — целый 0–127 и единственный источник
  звучащей высоты. Энгармоническое написание не хранится.
- `line` — необязательная табовая позиция (0–11), только место показа/ввода;
  она не меняет pitch. `voice` — GP-подобный голос 1–4 (голос 1 можно
  опустить). В pitched-ячейке на одной линии/позиции не более одной ноты
  на голос. Разные одновременно звучащие pitch-события сохраняются.
- `velocity` — необязательная динамика 1–127; при отсутствии временный
  синтез использует 90.
- Ударные используют pitch MIDI/GM (выборщик с GM-пэдами), а одновременные
  разные drum pitches не схлопываются даже если визуально попадают в одну
  семью/линию.

**Единицы** — доли родительского размера секции (`sec.timeSig ||
globalTimeSig`), те же, в которых живут `event.span` после
`getEventSpanInParentUnits`. Для 4/4 целый такт = 4 единицы,
`start: 1` — вторая четверть.

**Секция — якорь рулона.** При удалении секции её рулоны удаляются; при
клонировании секции рулоны копируются новому id (как клонируются
ритм-рулоны). Партия при этом остаётся независимой от ПРАВОК ГАРМОНИИ:
ресайз/деление ячейки, смена размера квадрата и модуляция ноты партии не
трогают (решение пользователя, п. 5). Модуляция транспонирует только
аккорды; партия остаётся как была — это осознанное решение, а не баг.

## 5. Схема файла

- Текущий `SONG_SCHEMA_VERSION` — **6**. Историческая миграция 4→5
  добавила `parts`; миграция 5→6 создаёт пустой `pitchRolls` и оставляет
  прежний `rolls` без конверсии.
- `sanitizeSongData` принимает только роли из allowlist, проверяет
  `pitch` как целое 0–127, velocity 1–127 и voice 1–4, отбрасывает битые
  pitch-события и дубли одной pitched-ячейки/голоса. Для ударных разные
  pitches на одной позиции остаются независимыми.
- Неизвестные ключи секций отбрасываются; при перенумерации id секций
  ключи обоих рулонов (`rolls`, `pitchRolls`) переносятся вместе.
- Экспорт `.struchord` и автосохранение включают оба домена и исходные
  метаданные инструментальной дорожки, если они известны.
- Старые песни загружаются без потерь: отсутствующий `pitchRolls`
  становится пустым объектом, tab-roll не переписывается.

## 6. Окно «Партии» (B-12.1)

- Вход: кнопка **«Партии»** в панели транспорта редактора (рядом с ▶ и
  «Лента»); выход — кнопка «Редактор» в шапке окна партий и Esc.
- Экран — отдельный слой по типу ленты (`body.is-parts`), редактор при
  этом скрыт, как в ленте.
- Содержимое: шапка с названием песни, имя активной партии, пустое
  состояние «Пока здесь пусто», при данных — табулатурная полоса.
- Табы: 6 линий (сверху 1-я струна), номера ладов в узлах сетки,
  тактовые черты по квадратам, подписи секций над полосой, повторы
  секций разворачиваются как на ленте. Масштаб — общий `--ui-scale`,
  горизонтальная прокрутка.
- Воспроизведение: партия звучит вместе с песней **в обоих режимах**
  (редактор и партии) тем же гитарным тембром; ноты планируются в общем
  планировщике (`scheduleNextEvent`) по той же сетке времени, что аккорды.

## 7. Критерий приёмки B-12.1

1. Старая песня открывается без ошибок, партий нет, показывается пустое
   состояние; в момент сдачи B-12.1 файл сохранялся с `schemaVersion: 5` (текущая версия — 6).
2. Демо-файл `dev/fixtures/b12-parts-demo.struchord` импортируется, в
   окне «Партии» видна табулатурная полоса с нотами, при ▶ партия звучит
   вместе с аккордами тем же тембром.
3. Повторы секций развёрнуты, ноты стоят в своих долях, тактовые черты
   совпадают с квадратами.
4. Редактор аккордов, лента и круг работают как прежде; `parts` не
   влияют на ступени, аппликатуры и определение тональности.
5. Корпус тестов зелёный (кроме двух известных инфраструктурных
   падений), добавлен сьют `b12-parts`, версия 0.620, кэш
   `struchord-v620`, строка в реестре релизов README/ROADMAP.

## 5. Кирпич 12.6 «Приёмы» — решения допроса R8 (2026-10-13)

Кирпич выбран пользователем вместо отменённых 12.4 «Нотный стан» и
12.8 «Пианоролл». Перед вопросами изучен GP8: пять групп эффектов,
символы табулатуры, клавиши, поведение dead slap / pick scrape.

### 5.1 Ответы пользователя (6 вопросов)

| # | Вопрос | Ответ |
|---|---|---|
| 1 | Объём | **Всё как в GP целиком** (не только «ходовые») |
| 2 | Звук | **Приближаем своим тембром** (без RSE) |
| 3 | Бенды | **Как в GP: редактор кривой** (bend / prebend / release / prebend+release) |
| 4 | Ввод | **Клавиши как в GP + палитра** с тултипами |
| 5 | Флажолеты | **Натуральные + искусственные** (окно параметров: тип, звучащая нота, лад правой руки) |
| 6 | Где действуют | **Только в партиях-табах**; аккордовый редактор не трогаем |

### 5.2 Границы кирпича

**Входит:** знаки приёмов на нотах партий и их приближённое звучание —
легато (H/P), слайды (legato/shift), бенды с кривой, вибрато (slight/wide),
палм-мьют, let ring, dead note, ghost note, акценты (обычный/сильный),
стаккато, теното, украшения (форшлаг до/на доле, мордент верхний/нижний,
тёрн и обратный, трель), тремоло-пикинг, fade in/out, натуральные и
искусственные флажолеты, тремоло-бар (как отдельный знак и как вибрато).

**Не входит:** RSE; приёмы в аккордовом редакторе/ленте (решение 6);
звук для dead slap и pick scrape — в GP они **только рисуются**, так же
делаем и мы; печать.

**Не меняется:** схема песни (остаётся 5) — все поля приёма
необязательные, старый файл и старый код читаются без потерь, как это уже
сделано с `dots`/`triplet`. Аккордовый редактор, лента, круг, ритм-рулон,
аппликатуры — без правок.

### 5.3 Данные (все поля — необязательные, на ноте партии)

```json
{ "start": 0, "dur": 1, "string": 5, "fret": 7,
  "legato": true,                                  // H/P: взятие без атаки из предыдущей ноты той же струны
  "slide": "legato" | "shift",                     // слайд В ноту (из предыдущей ноты той же струны)
  "bend": { "type": "bend"|"prebend"|"release"|"prebend-release",
            "points": [[0,0],[0.5,1],[1,1]] },     // t 0..1 от длительности, v в полутонах
  "vibrato": "slight" | "wide",
  "pm": true, "letRing": true, "dead": true, "ghost": true,
  "accent": 1 | 2,                                 // 1 — акцент, 2 — сильный
  "staccato": true, "tenuto": true,
  "grace": { "fret": 5, "onBeat": false },         // форшлаг: короткая нота перед/на доле
  "ornament": "mordent"|"upper-mordent"|"turn"|"inverted-turn",
  "trill": true,                                   // трель со следующей ступенью (лад +1 в пределах ≤24)
  "tremolo": true,                                 // тремоло-пикинг
  "fade": "in" | "out",
  "tremBar": true,                                 // тремоло-бар (знак + нырок высоты)
  "harm": { "type": "natural"|"artificial"|"pinch"|"tap"|"semi"|"feedback",
            "note": "E6" }                          // для искусственных — звучащая нота
}
```

Санитайз (как всегда — «отбросить, а не зажимать»): неизвестный тип
сбрасывается; `points` — до 8 точек, `t` зажат 0..1, `v` в −24..+24, первая
точка всегда `[0,0]` у `bend`/`prebend-release`; `accent` только 1 или 2;
`grace.fret` 0..24; `harm.note` проверяется через `noteToFrequency`;
`trill`/`tremolo`/`fade`/`tremBar` — строго `true|false`.

### 5.4 Звук: чем именно приближаем (без RSE)

| Приём | Что делаем в синтезе |
|---|---|
| Легато H/P | вторая нота без атаки: буфер играется со смещением (пропускаем щипок), громкость как у предыдущей |
| Слайд (legato/shift) | доезд высоты: `playbackRate` от частоты предыдущей ноты к своей за время слайда (shift — с атакой в начале, legato — без) |
| Бенд | кривая из `bend.points` → кусочно-линейный `playbackRate` по времени ноты (prebend — уже поднятая нота; release — спуск; prebend-release — подъём и возврат) |
| Вибрато | качание ±0.25 пт (slight) / ±0.6 пт (wide) с частотой ~6 Гц (несколько коротких линейных рампов) |
| Палм-мьют | короче (×0.35), глуше (brightness ×0.5), тише (×0.7), быстрый спад |
| Let ring | не режем по написанной длительности: звенит до следующей ноты этой струны/конца окна (потолок 6 с) |
| Dead note | очень короткий щелчок (0.05–0.08 с), без тона: низкий gain и высокий brightness |
| Ghost note | тише (×0.45) |
| Акцент / сильный | громче (×1.35 / ×1.6) |
| Стаккато / теното | стаккато режет длительность (×0.4), теното — не режет до конца написанного |
| Форшлаг | короткий (≈1/32) щипок на полтона-тон ниже/на заданном ладу прямо перед основной нотой |
| Мордент / тёрн / трель | быстрые чередования с соседней ступенью (лад ±1, ±2) в пределах длительности ноты |
| Тремоло-пикинг | повторные удары тем же ладом (≈1/16 от длительности доли) |
| Fade in/out | рампа громкости в начале/конце ноты |
| Натуральный флажолет | высота по узлу: лад 12 → +12 пт, 7 → +19, 5 → +24, 4 → +28, 3 → +31, прочее → +12 (октава) |
| Искусственный | высота из «звучащей ноты» окна параметров (`noteToFrequency`), таб показывает A.H./P.H./T.H./S.H. |
| Тремоло-бар | нырок высоты: спуск до −2 пт и возврат за длительность ноты |

### 5.5 Знаки на табах (как в GP)

| Приём | Как нарисовано |
|---|---|
| Легато H/P | дуга-лига между нотами |
| Слайд | наклонная линия между номерами ладов |
| Бенд | стрелка со величиной (`1`, `1/2`, `full`) над номером |
| Вибрато | волна над номером |
| Палм-мьют | «PM» над табом + пунктирная линия до конца действия |
| Let ring | «L.R.» над табом |
| Dead note | `x` вместо лада |

**Реализационные уточнения итерации 1 (0.624).**

- **Полки знаков.** Струны на стане стоят через 9 единиц viewBox, а фишка
  ноты занимает 16 — внутри стана знак лёг бы на соседнюю струну. Знаки
  вынесены за линейки (в GP линия PM тоже идёт над табом) и живут полками:
  сверху — пунктир PM, подписи PM и L.R.; снизу — артикуляция, акценты,
  стрелки fade. Запас `viewBox` считается по РЕАЛЬНО занятым полкам, поэтому
  стан без знаков остаётся геометрией 12.3.
- **Отличие от GP по клавише теното:** `Shift+T` вместо `Shift+−` — `_` с
  0.621 значит «длиннее» (решение пользователя). Экранный знак тот же «—».
- **Взаимоисключения:** стаккато ↔ теното, fade in ↔ fade out снимают друг
  друга (в GP это знаки одного смысла).
**Реализационные уточнения итерации 4 (0.627).**

- **Натуральный флажолет** считается от ОТКРЫТОЙ струны по узлу лада
  (12 → +12 пт, 7 → +19, 5 → +24, 4 → +28, 3 → +31, прочее → +12), а не от
  прижатого лада: флажолет на 12-м ладу звучит как нота 12-го лада, на
  7-м — как нота 19-го.
- **Искусственный флажолет** без читаемой «звучащей ноты» не ставится ни
  нотой, ни чтением файла: знак без высоты показывал бы приём, которого не
  слышно. Тип и нота запоминаются палитрой и переходят к следующим нотам.
- **Украшения играются сдвигом `playbackRate`** (±полутон), а не соседним
  ладом: приём работает и на границе грифа; тёрн/мордент не снимают знаки
  ноты, трель и тремоло-пикинг собираются одним планом ударов
  (`partStrokePlan`).
- **Форшлаг** — короткий щипок (≈1/32) перед нотой; «на доле» основная нота
  сдвигается на длину форшлага. Клавиша `G` (в GP8 отдельной клавиши нет),
  `Alt+G` — «на доле», «форшлаг N» в поиске задаёт лад.
- **Тремоло-бар приоритетнее слайда, но уступает бенду**: если у ноты есть
  кривая бенда, высоту ведёт она.
- **Dead slap и pick scrape** — знаки без звука: подписаны `slap` и
  `scrape` над станом (глифы GP — фирменные картинки).
- **Знаки живут полками над станом** (флажолет, трель, украшение, форшлаг,
  слэп, скребок): номер лада занимает 16 единиц при шаге струн 9, поэтому
  внутрь стана знак не пускается — правило 12.6.1. Запас вокруг стана
  считается по фактически занятым полкам.

**Реализационные уточнения итерации 3 (0.626).**

- **Окно кривой** живёт вне списка дорожек (`#partsBend` рядом с `#partsBody`):
  перерисовка табулатур его не сносит. Шаг высоты точки — четверть тона,
  точек не больше восьми, первую точку не сдвинуть и не убрать.
- **Мышь и модель:** во время перетаскивания меняются только кружок и линия
  (правило 60 fps), модель — один раз по `pointerup`, одной командой Store.
- **Вибрато после бенда** качается вокруг ПОДТЯНУТОЙ высоты (центр — значение
  последней точки кривой), а не вокруг написанной.
- **Бенд приоритетнее слайда** на той же ноте: кривую высоты ведёт кривая
  бенда; легато с бендом сочетается (прижим лада + подтяжка).
- **Знак на табе** — стрелка направления и величина долями тона (`full`,
  `½`, `¼`, `1¼`), своя полка над станом; полка тратится, только если бенд
  есть в системе.

**Реализационные уточнения итерации 2 (0.625).**

- **Легато высоту не тянет.** Хаммер ставит палец на лад сразу: голос берёт
  свой буфер со смещением 20 мс, но `startRate` не меняет. Наклон высоты —
  только у слайда (в GP у ноты с H/P наклона тоже нет).
- **Тремоло-пикинг — серия ударов**, а не отдельный голос: планировщик
  повторяет щипок каждую 1/16 длительности доли (шаг считается в долях
  четверти, поэтому 6/8 и 4/4 звучат одинаково), потолок — 24 удара.
  В предпросмотре тремоло играет один удар — там нужен знак, а не серия.
- **Кривая высоты — чистая функция** `partRateCurve`: планировщик применяет
  её к `playbackRate`, а тесты проверяют без звуковых узлов.
- **Слой голоса.** В `pluckString` добавлены необязательные `fadeIn`,
  `fadeOut`, `releaseAt`/`releaseTime` (обрыв с реально звучащей громкости) и
  `skipAttack` (смещение в буфере — понадобится легато в 12.6.2). Без
  параметров поведение прежнее.

### 5.8 Критерии приёмки

1. Любой приём ставится с клавиатуры и из палитры, снимается повторным
   нажатием; вся правка — одна команда Store и один шаг `Ctrl+Z`.
2. Знак виден на табе в том виде, что описан в 5.5, и **на звук влияет**
   (кроме dead slap / pick scrape — они только знаки, как в GP).
3. Файл: приёмы уезжают в песню необязательными полями, песня старого
   формата грузится без изменений, испорченные значения отбрасываются.
4. Курсор, ввод цифрами, длительности и все операции 12.2–12.3 работают
   ровно как раньше (регресс-проверки `b12-input.js`, `b12-parts.js`,
   `b12-tracks.js` зелёные).
5. Аккордовый редактор, лента, круг и ритм-рулон не меняются.

## 6. Кирпич 12.5 «Микшер» — разведка GP8 (2026-10-13)

Пользователь перед микшером сказал «изучи гтп»: где в Guitar Pro живут
громкость, панорама, mute/solo. Изучено по официальной документации GP8
(Global View, Automations, Tuning Settings) и по обзорам.

### 6.1 Что в GP8 есть (факты, на которые опираемся)

- **Микшер — это Global View**, панель внизу окна (F8 или кнопка в
  тулбаре). Она одновременно и микшер, и обзор партитуры: клик по такту
  переводит туда курсор, можно выделять несколько тактов и дорожек.
- Колонка дорожки: имя, перестановка «выше/ниже», «глаз» (показывать в
  мультидорожном виде), **Mute**, **Solo**, **Focus/Unfocus**, слайдер
  **громкости**, ручка **панорамы**, **эквалайзер**, а рядом с громкостью и
  панорамой — кнопка **автоматизации** (буква A).
- **Мастер-полоса**: ручка **focus** (поднять/понизить текущую дорожку, не
  трогая её слайдер), общая громкость и панорама, mute/solo мастера.
- **Focus ≠ Solo**: solo глушит остальные дорожки, focus просто приглушает
  их, сохраняя ансамбль слышимым.
- **Автоматизации** (F10): громкость, панорама, темп — точками по времени;
  у каждой точки «constant until next point» или «progressive to next
  point». Есть «Remove automations».
- Звук дорожки (тембр, эффекты, эквалайзер, струнные настройки) живёт **не
  в микшере**, а в Track Inspector справа.
- Значения микшера — часть песни (файла), а не только сессии.

### 6.2 Каподастр в GP8

- Каподастр — **свойство дорожки**: Track Inspector → Musical notation →
  Tuning → шестерёнка → **Capo** (по всему ладу) и **Partial capo**
  (частичный: на одну или несколько струн; номера ладов **абсолютные**,
  частичный каподастр независим от основного; поставленный ниже основного —
  не действует). Оба можно ставить одновременно.
- При смене строя/каподастра GP спрашивает: **Keep fingering** (ничего не
  транспонируется, табулатура остаётся как была) или **Adjust fingering**
  (аппликатура пересчитывается так, чтобы **высоты нот остались прежними**).
- В инспекторе видно «transposition tonality» — например, при каподастре на
  2-м ладу: «C played as D».
- Общая настройка File → Stylesheet → System & Staves: «capo and shifted
  tunings impact standard notation» — влияет ли каподастр на нотный стан.
- На стане каподастр показан значком/надписью над системой.

**Ранее принятое решение пользователя:** каподастр у нас — «как в GP,
пересчётом позиций» (аналог **Adjust fingering**: числа на табах
пересчитываются, высоты нот остаются записанными), а не «сдвигом звука».

### 6.5 Итерация 12.5.4 «Каподастр» — решения и реализация

Допрос R8 (2026-10-13), ответы и поправка пользователя:

| # | Вопрос | Ответ |
|---|---|---|
| 1 | Кто получает каподастр | **И партии, и песня** |
| 2 | Режимы | **Оба, как в GP**: при смене спрашиваем «оставить аппликатуру» (Keep fingering) или «пересчитать» (Adjust fingering) |
| 3 | Что делает «пересчитать» | Вариант 1: номера ладов пересчитываются, **высоты сохраняются**; неиграбельные ноты — **октавой вверх** со списком затронутых нот |
| 4 | Песня | Каподастр песни аппликатуры **не трогает**: над лентой появляется надпись «каподастр N», звук аккомпанемента поднимается на N полутонов |

Раскладка по коду 12.5.4:

- **Модель:** `part.capo` (0…12, 0 — нет каподастра) и `song.capo`. Запись
  в файл — только когда каподастр есть; чтение зажимает диапазон.
- **Звук:** каподастр — множитель высоты: `2^(capo/12)` в `partOpenFreqs`
  (ноты дорожки, флажолеты, предпросмотр) и в `songStringFreqs`
  (аккомпанемент целиком: бой, перебор, одиночные струны).
- **Пересчёт (Adjust):** `fret' = fret + старый − новый`; если номер вышел за
  гриф — сдвиг на октаву в подходящую сторону (вверх для нижней границы, как
  решил пользователь, вниз — для верхней); если и там не помещается, нота
  остаётся как была и попадает в список предупреждения. Форшлаг нота едет
  вместе с нотой.
- **Окно выбора** (`#partsCapo`) открывается при смене каподастра дорожки,
  если у дорожки есть ноты: показывает оба режима, для пересчёта — список
  затронутых нот ДО применения. Каподастр песни спрашивать не о чем
  (аппликатуры не пересчитываются) — он ставится сразу.
- **Знаки:** у дорожки — «капо N» на карточке, у песни — плашка «каподастр N»
  в шапке каждой секции ленты (в GP каподастр тоже печатается над системой)
  и выбор на карточке канала «Песня» в микшере.
- **Частичный каподастр (на отдельные струны)** — в GP есть; у нас не
  делается этой итерацией, идея записана в Активный бэклог ROADMAP (R2) как
  **B-103** (номера строк на струнах абсолютные, частичный капо ниже основного
  не действует — как в GP).

**Реализационные уточнения 12.5.4 (0.631).**

- **Где живёт каподастр.** `part.capo` — необязательное поле дорожки,
  `song.capo` — песни (`serializeCurrentSong`, `sanitizeSongData`);
  `songCapo` — состояние редактора, читается в `loadSong` до первой отрисовки.
  Значение по умолчанию (0) не пишется, диапазон зажимают `capoNumber` и
  `capoNumber` же при чтении; у песни поля не было раньше, поэтому старые файлы
  читаются как «без каподастра».
- **Звук.** Каподастр — это поднятый строй, а не транспозиция нот: множитель
  `2^(N/12)` встаёт в `partOpenFreqs` и `songStringFreqs`, поэтому дальше всё
  как обычно (`open * 2^(fret/12)`, флажолеты от открытой струны, бас — свои
  четыре струны).
- **Пересчёт — только у дорожки.** План (`partCapoPlan`) считает
  `fret' = fret + старый − новый` и возвращает `{ rolls, moved, kept }`, где
  `moved` — что именно поедет (секция, струна, откуда, куда, октава), `kept` —
  что осталось. Форшлаг едет вместе с нотой. Каподастр песни аппликатуры не
  пересчитывает вовсе — в этом и разница (решение пользователя, п. 4).
- **Октава — зеркально.** Нота ниже нуля едет октавой вверх (решение
  пользователя), нота выше 24-го лада — октавой вниз: вверх было бы ещё
  дальше за гриф. Обе ситуации попадают в список, и обе отменяются одним
  `Ctrl+Z`. Ветка `kept` (лад, которому не хватает грифа даже с октавой)
  недостижима при каподастре ≤ 12 и ладах ≤ 24 — оставлена как защита на
  будущее (импорт `.gp5` в 12.9 приедет с другими грифами) и покрыта тестом
  на выдуманном объекте.
- **Окно `#partsCapo`** открывается из `setPartCapoRequest` только когда у
  дорожки есть ноты (пустая дорожка ставится молча — спрашивать не о чем) и
  наполняется ПОСЛЕ показа окна (урок 12.5.3: закрытое окно молчит). Кнопки:
  «Оставить аппликатуру», «Пересчитать», «Отмена»; «Отмена» возвращает выбор
  в панели.
- **Два места выбора + плашка.** Панель дорожки — `#ptCapo` («Нет», «Капо
  1…12»); у песни дорожки-двойника нет, поэтому её каподастр живёт в карточке
  канала «Песня» (`[data-act="songCapo"]`). На карточке дорожки — пометка
  «капо N», над лентой у песни — плашка «играть с каподастром N» в шапке
  каждой секции; плашку перерисовывает и быстрый путь B-25
  (`syncSectionHeaderDom`), иначе она слетала бы при правке модуляции.

**Реализационные уточнения 12.5.3 (0.630).**

- **Объём уточнён пользователем:** «автоматизация нужна только для смены
  тембра». Громкость/панорама/темп точками по графику (F10 в GP) не делаем —
  вместо них звуковые автоматизации (Sound Automations): дорожка и «Песня»
  меняют звучание по ходу песни.
- **RSE не используем** (закрытый движок Arobas, лицензирован только в GP) и
  записанных библиотек у нас нет, поэтому звучания — свой синтез: яркость,
  сустейн (звон), доля корпуса и перегруз. Пресеты: «Акустика» (как было),
  «Чистый», «Перегруз», «Соло», «Эмбиент»; у баса четыре — «соло» басу не
  выдумываем.
- **Перегруз** — мягкое ограничение `0.75·tanh(k·x)/tanh(k) + 0.25·x`
  (`k = 1.5 + 3.5·amount`) и фильтр кабинета (2.4–5.2 кГц) с тримом
  `1/(1+0.45·drive)`: без примеси линейного сигнала сатурация съедала бы удар
  медиатора и звучала синтетически.
- **Точка автоматизации живёт в единицах сетки секции** (`{sec, unit, sound}`)
  — в той же валюте, что `start`/`dur` нот, поэтому попадает ровно в долю.
  Действует **до следующего переключения** или до конца песни, в том числе
  через границу секции (проверено тестом): в GP автоматизация тоже не
  сбрасывается на границе такта.
- **Подписи:** у дорожек — полка над станом (`звук: перегруз`), у «Песни» —
  пометка `♪` в ячейке ленты: своего стана у аккомпанемента нет. Полка
  тратится, только если в системе есть переключение.
- **Файл:** `part.sound`/`part.soundAuto` и `song.sound`/`song.soundAuto`.
  Значение по умолчанию и пустой список не пишутся; мусор (чужое звучание,
  секция вне карты, точка за длиной секции) отбрасывается.
- **Разметка ячейки ленты живёт в ДВУХ местах** (полный `render()` собирает
  свой шаблон, а `buildSquareInnerEventsHtml` — инкрементальный): пометка
  тембра добавляется в оба, иначе она появлялась бы только после дорисовки
  одной ячейки. Сведение шаблонов — отдельная волна (R5).

**Реализационные уточнения 12.5.2 (0.629).**

- **Три полосы, а не график:** низ — полка 250 Гц, середина — колокол 1 кГц
  (`Q = 0.8`), верх — полка 4 кГц; по ±12 дБ. В GP ползунки эквалайзера
  живут в Global View рядом с громкостью и панорамой — у нас там же, кнопкой
  `EQ`, которая разворачивает блок полос под каналом.
- **Место в цепочке:** вход канала → EQ → панорама → мастер. Эквалайзер
  стоит после сведения «щипок + корпус», поэтому полосы действуют на весь
  голос, а не на одну из ветвей. У мастера полосы включены сразу после его
  громкости (`громкость → EQ → панорама → выход`).
- **Ноль не хранится:** полоса «по нулям» — значение по умолчанию, в файл не
  попадает (как и остальной микшер); вернули полосу в ноль — ключ `eq` ушёл.
  Мусор в массиве становится нулём, выход за ±12 дБ зажимается.
- **Разворот блока — не правка песни:** `mixerEqOpen` — состояние вида
  (в файл и в историю не пишет), но переживает перерисовку окна партий.
- **Числа — целые децибелы:** шаг ползунка 1 дБ, подпись со знаком (`+6`).

**Реализационные уточнения 12.5.1 (0.628).**

- **Solo глушит «Песню»** тоже: в GP solo глушит все остальные дорожки, а
  аккомпанемент у нас — такая же дорожка микшера. Это записано тестом.
- **Focus — настройка прослушивания**, не данные песни: в файл не пишется,
  при загрузке песни сбрасывается в нейтраль (100 = без надбавки).
- **Протяжка ползунка** идёт через временный `mixerPending`: во время
  движения меняется только звук, модель — одна команда Store по отпускании
  (правило 60 fps и один шаг `Ctrl+Z`).
- **Карточки каналов не пересобираются** при перерисовке окна партий —
  протяжка не теряет элемент, по которому тянут.
- **Файл пишет только неумолчательные значения** (`mix` у партии и песни),
  поэтому обычная песня не растёт; схема остаётся 5.

## 8. Кирпич 12.7 «Знаки структуры» — решения допроса R8 (2026-10-13)

### 8.1 Ответы пользователя

| # | Вопрос | Ответ |
|---|---|---|
| 1 | Объём кирпича | **Полный набор, как в GP**: вольты (1-я/2-я концовки), черты повторов, D.C., D.S., Segno, Coda, To Coda, Fine, показ темпа |
| 2 | Звук | **Строго по знакам**: знаки реально меняют порядок проигрывания (сейчас играем линейно с повторами) |
| 3 | Показ | **И на ленте, и на табулатурах** партий |
| 4 | Темп | **Переиспользовать BPM секции**: знак «♩=N» показывает уже существующий `sec.bpm`, новых сущностей в модели нет |

Итерации (одна волна, три шага подряд): **12.7.1 «Модель и знаки на ленте»** →
**12.7.2 «Порядок прохода и звук»** → **12.7.3 «Знаки на табулатурах»**.

### 8.2 Теория, на которую опираемся

Проверено по источникам (общая теория нотной записи, GP следует тем же правилам):

- **Повтор**: конец повтора (`:|`) отправляет назад к парной черте начала
  (`|:`) или, если её нет, к началу пьесы;
- **Вольты**: квадрат с `volta = k` играется только в k-м проходе
  обрамляющего повтора; при прыжке по D.C./D.S. первые концовки
  пропускаются;
- **D.C.** — «с начала», **D.S.** — «от знака Segno»;
- **al Fine** — играть до знака **Fine**; **al Coda** — играть до знака
  **To Coda**, затем прыжок на знак **Coda**;
- **Fine** — точка остановки только после D.C./D.S. al Fine; **To Coda** —
  только после D.C./D.S. al Coda; сами по себе эти знаки ничего не делают;
- повторы внутри участка играются как обычно при каждом проходе.

### 8.3 Модель (все поля необязательные, схема файла не растёт)

Ставим знаки **на квадрат** — это минимальная единица нашей структуры (у нас
не такты), поэтому один знак всегда попадает в одну клетку и в одну долю
времени. «Поставить на секцию» = поставить на её первый квадрат.

- `sq.volta = 1…9` — номер прохода (вольта: `1.`, `2.`, …);
- `sq.mark = 'segno' | 'coda' | 'fine' | 'toCoda'` — знак-метка;
- `sq.jump = { type: 'dc' | 'ds', target: 'fine' | 'coda' | 'end' }` — знак
  перехода и его цель (D.C. al Fine, D.S. al Coda, D.C. al End и т.д.);
- `sq.repeatOpen = true` / `sq.repeatClose = true` — черты повтора, когда
  нужно несколько повторов внутри одной секции (`sec.repeat` и `sq.repeat`
  уже есть и продолжают работать);
- темп — существующий `sec.bpm`; знак «♩=N» только показывает его.

### 8.4 Порядок прохода (12.7.2)

Одна чистая функция `structurePlayOrder()` даёт массив шагов
`[{ secId, squareId, pass }]` — порядок, в котором песня играется:

1. линейный обход с разворачиванием `sec.repeat` и `sq.repeat`
   (их нынешняя логика сводится сюда, чтобы не было двух правд);
2. вольты: шаг попадает в проход только своего номера;
3. переходы: по встрече `jump` — прыжок к началу пьесы (`dc`) или к метке
   `segno` (`ds`); при `target = 'coda'` играем до метки `toCoda` и уходим на
   `coda`; при `target = 'fine'` — до метки `fine`; `'end'` — до конца;
4. защита от бесконечного кольца (счётчик прыжков), чтобы неверная разметка не
   вешала проигрывание.

### 8.5 Показ (12.7.1 — лента, 12.7.3 — табулатуры)

- **лента**: у квадрата — бейдж вольты («1.», «2.») и значки знаков
  (Segno, Coda, Fine, To Coda, «D.C. al Fine» и т.п.); черты повтора — рамкой
  квадрата; у секции с собственным темпом — знак «♩=N»;
- **табулатуры партий**: те же знаки на системе — в начале системы метки
  (Segno/Coda/темп/каподастр), в конце — черты повтора, вольты рамкой над
  системой, как GP печатает знаки над станом;
- постановка и снятие — из меню квадрата (у квадрата уже есть кнопка действий
  и бейджи) и палитры партий, группой «Структура»; повторное нажатие снимает
  знак (как у приёмов 12.6).

### 8.6 Итерация 12.7.1 «Модель и знаки» — что сделано (0.632)

- **Модель**: поля квадрата `volta` (1…9), `mark` (`segno|coda|fine|toCoda`),
  `jump` (`{type:'dc'|'ds', target:'fine'|'coda'|'end'}`), `repeatOpen`,
  `repeatClose` (строго `true`). Читатели `structureVoltaOf` / `structureMarkOf` /
  `structureJumpOf` / `structureRepeatOpen` / `structureRepeatClose` отбрасывают
  мусор поштучно — и в живом коде, и в санитайзе файла (`asSafeInt` вольту бы
  зажал, поэтому там проверка «целое 1…9»).
- **Запись в файл**: необязательные поля рядом с `repeat`/`customBeats`;
  «пусто» не пишется вовсе — обычная песня в файле не растёт, схема не меняется.
- **Лента**: подпись `structureBadgeShort` у квадрата (`1.`, `2. Segno`,
  `D.C.→Fine`), пустая — «…» (проявляется при наведении); полная строка со
  чертами — в подсказке (`structureBadgeText`, «1. :| Segno D.C.→Fine»); черты
  повтора — рамкой карточки (`.square--repeat-*` + псевдоэлементы на
  `.square-inner`: на `.square` рамка уезжала к краю ряда — проверено
  скриншотом); темп секции — знак «♩=N» (прежний `sec.bpm`, новых сущностей нет).
- **Панель знаков** `openStructureControls` — поповер у подписи, как панель
  модуляции: строки «Вольта», «Черты», «Метка», «Переход», «Цель»; активный
  вариант подсвечен, «Нет» снимает знак, «Цель» без перехода не действует,
  закрытие — Escape и клик вне панели. D.C./D.S. создают переход с целью Fine
  (или сохраняют уже выбранную цель), чтобы первый же клик давал рабочий знак.
- **Отмена и горячий путь**: вся правка — одна команда Store (`square/structure`);
  подпись и рамка обновляются на месте (`syncSquareStructureDom`, быстрый путь
  B-25), полного `render()` нет.
- **Тесты**: `dev/tests/b12-structure.js` — 30/0 (модель, файл, лента, темп,
  панель, отмена). Остальные партийные сьюты без изменений.

### 8.7 Итерация 12.7.2 «Порядок прохода» — что сделано (0.633)

- **Ходьба**: `findNextEvent` получил состояние хода (`walk`) и ведёт песню по
  знакам. Состояние переходит **иммутабельно** (шаг возвращает новое), поэтому
  превью следующего аккорда в подсказке не сбивает реальную игру.
- **Регионы**: `structureRegionOf` — от `|:` до парного `:|` (без `|:` повтор
  идёт от начала пьесы, как в нотах); число проходов стоит на закрывающей черте
  (`Math.max(2, sq.repeat || 1)`), панель знаков ставит `repeat = 2` вместе с
  чертой — как `:|` в GP.
- **Вольты**: `structureVoltaPlays` — играется только свой проход; если концовок
  меньше проходов, старшая играется и в последнем. Пропуск концовки с `:|` всё
  равно обрабатывает границу повтора (иначе терялся бы третий проход).
- **Прыжки**: `structureJumpDestination` (D.C. → начало, D.S. → Segno или
  начало), цель `jump.target` — «Fine» кончает пьесу, «To Coda» уводит на
  `coda` и дальше до конца, «Конец» просто играет вперёд. Один знак срабатывает
  один раз (`taken`), всего прыжков не больше `STRUCTURE_MAX_JUMPS = 4`, шагов
  ходьбы не больше 4000 — защита от неверной разметки.
- **После прыжка** (`afterJump`) повторы не берутся: `×N` секции и квадрата
  пропускаются, проход региона считается последним — первые концовки
  пропускаются, вторые играются (правило GP).
- **Стык с прежним**: песня без знаков играет ровно как раньше; прежние
  счётчики повторов (`_sectionRepeatCount`/`_squareRepeatCount`) сохранены —
  лента по ним считает номера проходов. Ход живёт в `playbackState._structureWalk`:
  старт — с чистого листа (или из позиции ленты при старте «отсюда»), пауза
  сохраняет ход, перезапуск с той же позиции (смена BPM на ходу) ход не теряет,
  стоп обнуляет.
- **Тесты**: `dev/tests/b12-structure-play.js` — 26/0 (прежнее поведение,
  регионы, вольты, D.C./D.S./Fine/Coda, счётчик прыжков, зацикливание,
  иммутабельность, превью и настоящий `scheduleNextEvent`).

### 8.8 Итерация 12.7.3 «Знаки на табулатурах» — что сделано (0.634)

- **Раскладка**: `partStructureLayout(sec, parentTs)` переводит знаки квадратов в
  единицы сетки секции (те же, что у бар-линий и нот) — одна модель на ленту и
  таб, отдельных представлений нет.
- **Полки**: новые полки лэйаута станка `structure` (метки), `jump` (переходы),
  `volta` (скобки вольт), `tempo` (знак «♩=N»), все — ПОД знаками приёмов, чтобы
  знаки структуры стояли ближе к стану, а приёмы остались выше. Запас вокруг
  стана по-прежнему считается по реально занятым полкам: стан без знаков
  сохраняет геометрию 12.3.
- **Рисование**: метки и переходы — подписями у своего квадрата; черты повтора —
  толстой чертой с двумя точками (у `|:` точки справа, у `:|` слева); вольты —
  скобкой с номером, соседние квадраты одной вольты — одной скобкой; темп —
  «♩=N» в начале системы (глобальный темп не дублируется, он в шапке).
- **Оговорка**: знаки структуры стоят на квадрате и читаются самой ходьбой
  (`findNextEvent`), а не «только когда есть вольты». Поэтому `:|` и `|:` без
  вольт — это обычные границы региона повтора, а счётчик проходов берётся с
  закрывающей черты.
- **Тесты**: `dev/tests/b12-structure-tab.js` — 16/0 (метки, переходы, черты с
  точками, вольты, темп, «не наслаивается на струны», геометрия без знаков, бас).

## 9. Кирпич 12.9 «.gp5» — разведка формата (2026-10-13)

### 9.1 Что известно про форматы Guitar Pro

| Формат | Где | Что внутри | Читать | Писать |
|---|---|---|---|---|
| **.gp3 / .gp4 / .gp5** | GP3–GP5 (2000–2005) | плоский **бинарный** поток, little-endian, строки в **однобайтовой кодировке** (russian-файлы — cp1251, западные — cp1252) | да | да |
| .gpx | GP6 (2010) | проприетарный контейнер BCFZ + XML | да | да |
| .gp | GP7/GP8 (2017/2022) | обычный **ZIP** + `Content/score.gpif` (XML) | да | да |

Общая структура `.gp5` (сверено по спецификации сообщества, ссылки в 9.6):
шапка 30 байт `FICHIER GUITAR PRO v5.00/5.10` → сведения о песне
(название/исполнитель/альбом/слова/музыка/копирайт) → текст песни (5 строк) →
RSE/страница → **темп** → тональность → 64 канала плейбэка → **блок направлений**
(19 позиций: coda, segno, fine, D.C., D.S. и их «al Coda / al Fine» варианты) →
число тактов и дорожек → **мастер-такты** (размер, `|:`, число повторов,
вольты, метка секции, тональность, двойная черта) → **дорожки** (имя, число
струн, настройка 7 струн, канал/MIDI-инструмент, ладов, **капо**, цвет, флаги
таба/нот) → **такты**: на каждый такт × дорожку 2 голоса × доли × ноты.

Нота: лад, струна, длительность (`duration_percent` — `f8be`, big-endian!),
и приёмы: бенд с точками кривой, форшлаг, тремоло-пикинг, слайд (legato/shift,
вход/выход), флажолет, трель, палм-мьют, вибрато (в GP5 только «лёгкое»),
стаккато, dead note, ghost, акценты, динамика, аппликатура, tie.

### 9.2 Что из этого уже есть у нас

Наша модель (12.1–12.7) покрывает почти весь список **своими** средствами:

| GP | Наше поле |
|---|---|
| название/исполнитель | `metadata.title` / `metadata.artist`; альбом, слова, подзаголовок, композитор, копирайт и notice GP3–5 добавляются в `notes` (без привязки к долям) |
| темп + его смены по ходу | `sec.bpm` (знак «♩=N» из 12.7) |
| размер такта | `square.customBeats` + `event.timeSig` |
| `|:` / `:|` / число повторов | `square.repeatOpen/repeatClose/repeat` (12.7) |
| вольты (1-я/2-я концовки) | `square.volta` |
| метки и переходы (Segno/Coda/Fine/To Coda, D.C./D.S.) | `square.mark`, `square.jump` |
| такт с аккордовой схемой (chord diagram) | `event.chord` (имя аккорда) + `event.fingering` |
| дорожка: имя/исходное имя, роль, GM program/channel, строй, капо | `part.name`, `part.sourceName`, `part.instrument`, `part.gmProgram`, `part.midiChannel`, `part.tuning`, `part.capo` |
| голоса дорожки (в текущем редакторе до четырёх) | `rolls` для guitar/bass; `pitchRolls` для остальных ролей |
| негитарные высоты и velocity | `pitchRolls[secId]`: абсолютный MIDI `pitch` 0–127, необязательные `velocity` и `voice`; линия таба — только presentation/input position |
| приёмы ноты (бенд, слайд, PM, dead, ghost, акценты, вибрато, флажолеты, украшения, тремоло) | те же поля ноты, что ставит 12.6 |

### 9.3 Оставшиеся разрывы после 12.9.2 (исторический снимок перед 12.9.3)

1. **Импорт/экспорт форматов**: импорт GP3–GP5 завершён в 12.9.3; `.gp`, `.gpx`, MIDI и экспорт остаются в 12.9.5–12.9.8.
2. **Ручная разбивка секций**: «Сделать секцией» по выделенным тактам в табах и на ленте — 12.9.4; автоматические секции по GP-меткам либо одна лента без меток реализованы в 12.9.3.
3. **MIDI → tab**: автоподбор позиции по фразе — в 12.9.7, не в 12.9.2.
4. **Текст песни и заметки** (lyrics, notice, текст на доле) best-effort переносятся 12.9.3 в поле «Заметки» без привязки к долям; прочие потери перечисляются в отчёте.
5. **Качественные тембры / RSE** не реализуются: в 12.9.2 только простые синтетические pitched-тоны и разные короткие GM-подобные ударные.
6. **Нотный стан и переключатель таб/ноты** — 12.10. Пианоролл в согласованный текущий объём не входит.

### 9.9 Итерация 12.9.1 «Любой строй и число струн» — что сделано (0.635)

- **Модель**: `part.strings` — массив нот от низкой струны к высокой; он же
  задаёт число струн (1…12). Порядок струн — как у частот открытых струн, а не
  как у GP (там обратный), поэтому `partTuningNotes` отдаёт массив прямо.
- **Порядок источников**: свой строй → пресет → «как в песне»; у баса «как в
  песне» остаётся нижними четырьмя струнами октавой ниже (`partSongDefaultNotes`).
- **Файл**: `part.strings` пишется только когда строй не совпадает ни с
  готовым, ни со строем песни; совпадение хранится ссылкой (`tuning`/`null`).
  Разбор из файла — **строгий**: либо все ноты годные, либо строй считается
  испорченным и отбрасывается целиком (поштучный отбор сдвинул бы нумерацию
  струн). Строй длиннее 12 нот обрезается, как и остальные длинные списки.
- **UI**: пункт «Свой строй…» в списке строёв панели дорожки открывает окно
  «Строй дорожки» (`#partsTuning`): строки по струнам (сверху высокая),
  выпадающие списки нот по хроматике (C0…B7), «+ струна» (на пять полутонов
  ниже самой низкой), «− струна», «Как в песне», готовые строи инструмента,
  подпись с числом струн и предупреждением о неиграбельных нотах. «Готово» —
  одна команда Store; отказ в вопросе про ноты окно не закрывает.
- **Тесты**: `dev/tests/b12-strings.js` — 33/0 (модель, файл, санитайз, звук,
  окно, применение/отмена, сужение, стан на 7 и 8 струн, прежнее поведение).

### 9.10 Итерация 12.9.2 «Негитарные дорожки и абсолютный MIDI pitch» — реализация

- **Роли**: allowlist `guitar / bass / drums / keys / vocal / other`;
  исходное `sourceName` не теряется при переименовании, валидные целые
  `gmProgram` (0–127) и `midiChannel` (1–16) переживают файл.
- **Два домена**: `rolls` остаётся гитаро-/басовым tab-roll; `pitchRolls`
  содержит `{start,dur,pitch,line,voice?,velocity?}`. Pitch строго целый
  0–127 (`C4=60`), без хранения энгармоники. `line` — независимая позиция
  временного таб-показа. Смена роли не конвертирует и не удаляет ни один
  домен; `rollStringLimit` сохраняет недостижимые tab-линии после перехода
  на более короткий гриф. Миграция v5→v6 добавляет pitch-roll, не переписывая старые табы.
- **Ввод и показ**: pitched-роли — временный GP-подобный гриф с E2–A2–D3–G3–B3–E4
  по умолчанию, ввод ладом 0–24 или кликом; ударные — отдельные GM-пэды.
  До четырёх голосов позволяют хранить одновременные события; на одной
  pitched-линии/позиции в одном голосе одна нота. Разные одновременные
  drum pitches не схлопываются. Недоступный текущему грифу pitch не
  зажимается/не транспонируется/не удаляется — помечен как непригодный.
- **Звук**: клавиши/вокал/прочее — простые временные тоны; барабаны — разные
  короткие синтетические генераторы GM-подобных hit-ов. Velocity влияет на
  громкость, умолчание — 90. Ни RSE, ни семплов/«качественных» тембров.
- **За границей 12.9.2**: импорт GP3–GP5 (реализован следующим релизом
  12.9.3/0.637), `.gp`/`.gpx`/MIDI, MIDI-автоподбор позиции, ручная разбивка
  секций (12.9.4–12.9.8), нотный стан и переключатель вида (12.10).
- **Проверки**: `b12-pitch.js` — 35/0; `b12-tracks.js` — 90/0;
  `b12-parts.js` — 50/0; `b12-strings.js` — 33/0;
  `b12-sounds.js` — 47/0; `b12-structure.js` — 30/0;
  `b87-song-metadata.js` — 34/0; `b662-sw-range-and-chime-log.js` — ALL OK;
  три inline-JS блока проходят `node --check`. В интеграции 0.637 полный
  `dev/run-tests.sh` завершился **123 ok, 0 FAIL**; B-68 требует запущенный
  локальный сервер на `127.0.0.1:8000`. SW cache этого релиза — `struchord-v637`.

### 9.11 Итерация 12.9.3 «Импорт Guitar Pro 3–5» — реализация (0.637)

- **Парсер и лицензия**: alphaTab 1.8.4 UMD встроен в `STRUCHORD.html` как
  инертный `text/plain` script и оценивается только при первом выборе GP-файла.
  Приложение остаётся одним офлайн HTML без сетевого runtime-запроса; MPL-2.0,
  исходные заголовки и notice интегрированных библиотек сохранены в
  `third_party/alphaTab/` и рядом с встроенным кодом. Закрывающий HTML-тег,
  встречавшийся внутри шаблона UMD, экранирован в JavaScript как `<\/html>`:
  хост-документ остаётся валиден, а код после вычисления возвращает исходную строку.
- **Предпросмотр**: поддерживаются `.gp3`, `.gp4`, `.gp5`; выбор всех дорожек
  включён по умолчанию, имя/роль/число нот/GM/channel/строй показаны до импорта.
  Автоопределение UTF-8, Windows-1251 или Windows-1252 можно исправить вручную;
  повторный разбор сохраняет текущие отметки дорожек. Доступны новая песня и
  overlay в текущую; при append старые части/секции остаются, дорожки источника
  накладываются с первого такта, отсутствующие секции добавляются в хвост.
- **Перенос данных**: GP-метки открывают секции, без меток весь источник — одна
  секция. Переносятся guitar/bass tab-ноты и tuning (1–12 струн), прочие роли —
  абсолютным pitch 0–127; сохраняются GM program/channel, четыре голоса,
  представимые эффекты (включая bend curves), начальные темп/тональность и
  текстовые поля GP в `notes`. Динамики pitch-нот best-effort преобразуются в
  velocity; названия дорожек/метаданные ограничиваются лимитами модели с записью
  потерь в отчёт. Лады 25–127 сохраняются в модели, остаются видимыми и
  отображаются пунктиром как недоступные; воспроизведение их пропускает.
- **Отчёт**: перечисляет количество выбранных/импортированных дорожек, исходных,
  перенесённых и пропущенных нот/тактов, секции, высокие лады, перенесённые
  эффекты/текст, не представимые знаки/поля, ограничения модели и причины
  потерь. Некомпонующийся размер такта исключается из карты отдельно: он и
  связанные ноты не выдаются за «перенесённую длительность»; позднейшие пригодные
  такты продолжают импортироваться. Append — одна команда Store для undo.
- **Проверки**: `dev/tests/b12-gp-import.js` — 31/0 (GP3/4/5, CP1251 и ручная
  коррекция кодировки, роли/GM, эффекты, лады 25/30 и пунктир, append/undo,
  маркеры/без маркеров, невалидная геометрия и отчёт, отсутствие сетевого
  runtime и jsdom-ошибок). Полный `dev/run-tests.sh` при сервере для B-68 —
  **123 ok, 0 FAIL**.

### 9.12 Итерация 12.9.4 «Сделать секцией» — реализация (0.638)

- **Тактовая адресация**: и на ленте, и в табах выбираются полные такты:
  обычный клик задаёт начало, Shift-клик — конец. Такт считается по
  числителю размера родительской секции (4/4 — четыре единицы, 3/4 — три),
  независимо от числа/длины chord-cells. Выделение — ровно один непрерывный
  диапазон по порядку секций; несмежные наборы не поддерживаются.
- **Вид табов**: партии собраны в непрерывные горизонтальные строки. Названия,
  размеры и проходы повторов — отдельные маячки над строками; таб-секции не
  оборачиваются в карточки. Подсветка диапазона рисуется в SVG и на ленте;
  границы сохраняют адресацию курсора и воспроизведения.
- **Преобразование модели**: «Сделать секцией» создаёт в `sections` новую
  секцию выбранного типа, а выбранные square/event-фрагменты переносятся туда
  по исходному порядку. Если тактовая граница пересекает длинную ячейку без
  отдельного ритма, event делится точно по сетке 1/16; аккорд и аппликатурные
  поля копируются, длительность каждой части сохраняет суммарный span. Все
  непокрытые префиксы/суффиксы остаются самостоятельными секциями на своих
  местах. Для диапазона с разными размерами секций исходный `timeSig` нужных
  событий становится явным, чтобы новая секция не транспонировала их доли.
- **Ноты и автоматизация**: ключи `rolls` и `pitchRolls` переназначаются к
  фрагментам; `start`/`dur` смещаются и масштабируются при смене родительского
  размера без clamp, потери pitch или удаления эффектов ноты. Автоматизация
  звука песни и дорожек (`songSoundAuto`, `part.soundAuto`) переносится по тем
  же границам. Пул ритма перед split материализуется штатной функцией.
- **Диалог и undo**: компактный диалог предлагает Intro, Verse, PreChorus,
  Chorus, Bridge, Solo, Outro и Custom (название до 200 символов). Вся правка
  модели — один `songStore.dispatch('section/make-range', ...)`, то есть один
  шаг Ctrl+Z; отмена диалога модели не касается.
- **Fail-safe ограничения**: частично выбрать повторяющуюся секцию нельзя;
  повторяющийся квадрат, группу повторов/переходов и ячейку со своим rhythm-roll
  через границу не режем. Для секционного рисунка ритма нельзя менять фазу
  частичным split/слиянием. Также отказ выдаётся, если выбор пересекает пустую

### 9.14 Итерация 12.9.6 «Импорт Guitar Pro 6 `.gpx`» — реализация (0.640)

- **Разведка формата.** `.gpx` — не ZIP: контейнер `BCFZ` (бит-поток LZ с
  литералами и ссылками назад) над файловой системой `BCFS` (блоки по 4096 байт,
  записи каталога с именем, размером и списком блоков). Внутри — тот же
  `score.gpif`, который уже читает встроенный alphaTab. Формат сверен на
  настоящих файлах GP6: два независимых декодера дали побайтово одинаковый
  результат; пришлось учесть две особенности — копирование может быть длиннее
  расстояния (ссылка на собственный хвост), а поток Guitar Pro иногда обрывается
  раньше объявленного размера.
- **Рантайм.** `dev/gpx-bcfz-runtime.js` — распаковщик BCFZ и чтение BCFS с
  лимитами (64 МБ файл, 128 МБ распаковка, 512 файлов, 32 МБ на файл) и отказами
  вместо догадок; вшит в `STRUCHORD.html` инертным скриптом и поднимается только
  при импорте, как ZIP-кодек 12.9.5. Энкодер для фикстур — `dev/tools/gpx-fixture.js`
  (только dev).
- **Импорт.** `score.gpif` нормализуется в синтетический ZIP и разбирается тем же
  alphaTab, поэтому переносятся те же данные и пишется тот же отчёт, что в
  12.9.5: ноты, ритм, размер, темп, тональность, повторы, вольты, метки,
  переходы, приёмы, lyrics, метаданные, роли, строй, капо, GM program/channel.
- **Кодировка.** Переключатель UTF-8 / Windows-1251 / Windows-1252 в предпросмотре
  (решение R8): ведущие нули выравнивания BCFS отбрасываются, текст
  перекодируется в UTF-8 перед разбором; переключение перечитывает только
  `score.gpif`, контейнер не распаковывается заново.
- **Вложения.** Записи BCFS проходят тот же отбор, что записи ZIP: поддерживаемые
  аудио-/графические файлы входят в медиа-манифест песни и в экспорт.
- **Опознание и отказы.** Расширение `.gpx` либо подпись `BCFZ`/`BCFS` в первых
  четырёх байтах; не-GP под именем `.gpx`, битый поток, превышение лимита и
  контейнер без `score.gpif` дают понятное сообщение без частичного импорта
  (решение R8). Обрезанный хвост и потерянные элементы контейнера перечисляются
  в отчёте отдельной строкой.
- **Решения R8 (2026-10-15):** объём — полный (сканер BCFS + перенос вложений);
  кодировка — переключатель в предпросмотре; нештатный файл — понятная ошибка без
  частичного импорта; источник эталонного файла — настоящий `.gpx` пользователя
  (синтетические фикстуры остаются для краёвых случаев).
- **Проверки:** `b12-gpx-container.js` — 23/0; `b12-gpx-import.js` — 17/0; полный
  `dev/run-tests.sh` — 128 ok, 0 FAIL. Приёмка на файлах пользователя из
  `uploads/` (в код не коммитятся): `monsoon.gpx` — 85 тактов, 3 дорожки, 2043

### 9.16 Итерация 12.9.7 «Импорт Standard MIDI File» — реализация

- **Задача.** Последний формат волны импорта: `.mid`/`.midi` должен открывать то же
  окно предпросмотра с выбором дорожек, что и Guitar Pro, и строить песню из тех же
  кирпичей (секции → таргеты по тактам → партии).
- **Разборщик.** `dev/midi-runtime.js` — UMD-модуль SMF: форматы 0/1/2, деление
  времени в тиках (SMPTE отклоняется), мета-события (темп 0x51, размер 0x58, ключ 0x59,
  имя трека 0x03, текст 0x01, метка 0x06, конец трека 0x2F), sysex, running status,
  note on/off с парой «канал + высота», program change, CC, aftertouch и pitch bend.
  Встраивается в `STRUCHORD.html` как невидимый блок `midiRuntime`
  (`dev/embed-midi-runtime.js`), поднимается лениво при первом MIDI-импорте и
  экранируется `dev/tools/escape-inert-blocks.js` вместе с остальными блоками.
- **Решения допроса (R8).** Дорожка → отдельная партия (имя трека или `Семейство · GM N`);
  абсолютный pitch без угадывания табулятуры; канал 10 → партия `drums` с картой GP;
  темп/размер/тональность из файла; секции по меткам, без меток — «Вся песня»;
  `CC7/CC6` → громкость микшера (значения ≤ 10 — шкала GP 0–10, иначе MIDI 0–127),
  `CC10` → панорама −100…+100; длительности квантуются к сетке с точками и тролями,
  отклонения перечисляются в отчёте.
- **Конвертация.** `midiTimeline` (темп, размер, `unitsPerQuarter`, длина такта, метки) →
  `midiBuildSections` (секции по меткам, группы по 128 тактов, пустые события) →
  `midiTargetForTick` (бинарный поиск по тикам) → `midiConvertTrack`. Гитара и бас
  пишутся в табулатурный рулон (`string` + `fret`, лад подобран по грифу партии через
  `partPitchPositions`), остальные инструменты — в pitch-рулон с `line` из карты GP.
  Столкновения по ячейке «секция + позиция + линия» решаются перебором голосов 1–4,
  как при импорте GP.
- **Режимы.** «Новая песня» собирает объект песни и зовёт `loadSongFromObject`;
  «Дописать в текущую» добавляет новые секции и партии через `gp/import-overlay`
  после существующих тактов — MIDI-ноты привязываются только к новым секциям, как
  при дописывании GP-файла.
- **Отчёт.** Общий рендер `gp35MakeReport` с заголовком «Отчёт об импорте MIDI»;
  отчёт MIDI несёт нейтральные значения полей GP-отчёта, а `transfers` принимает
  и `Set`, и массив.
- **Грабли, найденные на приёмке.** (1) Выдуманные имена констант в блоке конвертера
  давали `NaN` в пределе секции — цикл построения тактов обрывался, и импорт падал с
  «ни одна дорожка не дала нот»; константы переименованы в `MIDI_*` и берутся из
  `SONG_LIMITS`. (2) Приложение рисует гитару и бас **только** табулатурой, поэтому
  абсолютный pitch для них обязан превратиться в пару «струна + лад». (3) Метка на

  дорожки появляется только при program change — иначе он берётся из первой ноты,
  а в партии хранится 1…16, как в Guitar Pro.
- **Защита от повтора.** `dev/tests/b12-midi-import.js` (48 проверок) закрывает

### 9.15 Хотфикс 0.641 «Live Server ломал страницу» (вне кирпичей 12.9)

- **Симптом.** Через VS Code Live Server (порт 5500) под приложением шла огромная простыня

- **Разведка.** Три замера из консоли пользователя: `alphaTabRuntime.textContent.length` = 738 484

### 9.15 Итерация 12.9.8 «Экспорт в Guitar Pro 6 `.gpx`» — реализация (0.643)

- **Что за формат.** `.gpx` у Guitar Pro 6 — тот же контейнер `BCFZ`/`BCFS`,

  пользователя. Настоящий `.gp5` (BCZF) в эту итерацию намеренно не входит —
  отдельный кирпич.
- **Писатель GPIF.** `dev/gpif-writer.js` (встраивается инертным блоком
  `gpifWriterRuntime`, поднимается только при экспорте) собирает `score.gpif`:

  Связки (`<Tie>`) пишутся **прямым потомком `<Note>`**: внутри `<Properties>`
  alphaTab 1.8.4 их не видел.
- **Модель повторов.** GPIF повторов не хранит, поэтому секция с `repeat = N`
  разворачивается в N копий тактов, а отчёт прямо говорит об этом
  («Повторы секций записаны повторяющимися тактами»).
- **Микшер.** Громкость и панорама дорожки квантуются в 17 ступеней GP
  (шаг ≈ 6 %); импорт `.gpx`/`.gp` с 12.9.8 читает `Volume`/`Balance`, поэтому
  экспорт проверяется кругом. Длительности, которые не выражаются ритмами GP
  (например, 1.25 доли), перечисляются в отчёте как потерянные.
- **Решения R8 (2026-10-15):** один формат за итерацию с тщательной приёмкой;

  и потерянном; UI — окно выбора формата из существующей кнопки «Экспорт»;
  сначала BCFS/GP6, `.gp5` — следующим кирпичом; гитары и бас — таб-дорожки,
  остальные — pitch, ударные — пер-дорожки.
- **Связки при импорте.** alphaTab не отдаёт GPIF-идентификаторы нот, поэтому
  `<Tie>` из `score.gpif` сопоставляется очередью: ноты GPIF идут в порядке
  документа, и каждая нота разбора ищет свою пару по струне и ладу (таб) либо
  по высоте (pitch), после чего курсор сдвигается. Эвристика «склеивать соседние
  одинаковые ноты» отвергнута на приёмке: она молча портила независимые ноты.

  `b12-gpx-export.js` — 36/0 (круг экспорт → импорт: секции, такты, дорожки,
