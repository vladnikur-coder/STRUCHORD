## 2. Границы зонтика

**Входит:** многодорожечный табулатурный редактор — партии со своими
нотами (струна + лад), табы, ввод с клавиатуры, воспроизведение,
нотный стан, несколько дорожек, микшер, приёмы, знаки структуры,
стан, импорт/экспорт `.gp5`.

**Не входит:** RSE (реалистичный звуковой движок Guitar Pro) — звук
остаётся текущим гитарным тембром приложения. Печать/PDF (B-49) остаётся
откаченной и в кирпичи не возвращается без отдельной спеки.

**Не меняется:** текущий редактор аккордов, лента, круг, ритм-рулон,
аппликатуры. Партии живут параллельным режимом и связаны с песней общим
файлом и общим воспроизведением.

## 4. Модель данных (B-12.1)

Новая область песни — `parts`. Рулон — по секциям:

```json
"parts": [
  {
    "id": 1,
    "name": "Партия 1",
    "instrument": "guitar",
    "tuning": null,
    "visible": true,
    "rolls": {
      "1": [ { "start": 0, "dur": 1, "string": 0, "fret": 3 } ]
    }
  }
]
```

- `id` — целое, уникальное в песне (как у секций/квадратов).
- `name` — текст ≤ 60 символов; пустое имя → «Партия N».
- `instrument` — `guitar` (задел: `bass` в B-12.3). Незнакомое → `guitar`.
- `tuning` — `null` = строй песни (сейчас всегда; задел под B-12.3).
- `visible` — показывать партию (сейчас одна партия; задел под B-12.3).
- `rolls` — объект: ключ — **id секции**, значение — массив нот.
- Нота: `start` (позиция в единицах сетки секции, ≥ 0), `dur`
  (длительность в тех же единицах, > 0), `string` (0–5; **0 = 6-я струна
  (низкая E)**, как индексы в `shape` и `OPEN_CHORDS`), `fret` (0–24).

**Единицы** — доли родительского размера секции (`sec.timeSig ||
globalTimeSig`), те же, в которых живут `event.span` после
`getEventSpanInParentUnits`. Для 4/4 целый такт = 4 единицы,
`start: 1` — вторая четверть.

**Секция — якорь рулона.** При удалении секции её рулоны удаляются; при
клонировании секции рулоны копируются новому id (как клонируются
ритм-рулоны). Партия при этом остаётся независимой от ПРАВОК ГАРМОНИИ:
ресайз/деление ячейки, смена размера квадрата и модуляция ноты партии не
трогают (решение пользователя, п. 5). Модуляция транспонирует только
аккорды; партия остаётся как была — это осознанное решение, а не баг.

## 5. Схема файла

- `SONG_SCHEMA_VERSION` 4 → **5**.
- `SONG_MIGRATIONS[4] = migrateV4toV5` — проставляет `parts: []`.
- Санитайзер `sanitizeSongData` разбирает `parts` строго: лимиты,
  allowlist инструментов, целые id, ноты — конечные числа в диапазонах,
  незнакомые ключи секций отбрасываются. Id секций при загрузке могут
  пересобираться — ключи рулонов переносятся через карту id.
- Экспорт `.struchord` и автосохранение включают `parts`.
- Старые песни (v2–v4) загружаются с пустым списком партий — пустое
  состояние окна, ничего не теряется.

## 6. Окно «Партии» (B-12.1)

- Вход: кнопка **«Партии»** в панели транспорта редактора (рядом с ▶ и
  «Лента»); выход — кнопка «Редактор» в шапке окна партий и Esc.
- Экран — отдельный слой по типу ленты (`body.is-parts`), редактор при
  этом скрыт, как в ленте.
- Содержимое: шапка с названием песни, имя активной партии, пустое
  состояние «Пока здесь пусто», при данных — табулатурная полоса.
- Табы: 6 линий (сверху 1-я струна), номера ладов в узлах сетки,
  тактовые черты по квадратам, подписи секций над полосой, повторы
  секций разворачиваются как на ленте. Масштаб — общий `--ui-scale`,
  горизонтальная прокрутка.
- Воспроизведение: партия звучит вместе с песней **в обоих режимах**
  (редактор и партии) тем же гитарным тембром; ноты планируются в общем
  планировщике (`scheduleNextEvent`) по той же сетке времени, что аккорды.

## 7. Критерий приёмки B-12.1

1. Старая песня открывается без ошибок, партий нет, показывается пустое
   состояние; файл сохраняется с `schemaVersion: 5`.
2. Демо-файл `dev/fixtures/b12-parts-demo.struchord` импортируется, в
   окне «Партии» видна табулатурная полоса с нотами, при ▶ партия звучит
   вместе с аккордами тем же тембром.
3. Повторы секций развёрнуты, ноты стоят в своих долях, тактовые черты
   совпадают с квадратами.
4. Редактор аккордов, лента и круг работают как прежде; `parts` не
   влияют на ступени, аппликатуры и определение тональности.
5. Корпус тестов зелёный (кроме двух известных инфраструктурных
   падений), добавлен сьют `b12-parts`, версия 0.620, кэш
   `struchord-v620`, строка в реестре релизов README/ROADMAP.

### 5.1 Ответы пользователя (6 вопросов)

| # | Вопрос | Ответ |
|---|---|---|
| 1 | Объём | **Всё как в GP целиком** (не только «ходовые») |
| 2 | Звук | **Приближаем своим тембром** (без RSE) |
| 3 | Бенды | **Как в GP: редактор кривой** (bend / prebend / release / prebend+release) |
| 4 | Ввод | **Клавиши как в GP + палитра** с тултипами |
| 5 | Флажолеты | **Натуральные + искусственные** (окно параметров: тип, звучащая нота, лад правой руки) |
| 6 | Где действуют | **Только в партиях-табах**; аккордовый редактор не трогаем |

### 5.2 Границы кирпича

**Входит:** знаки приёмов на нотах партий и их приближённое звучание —
легато (H/P), слайды (legato/shift), бенды с кривой, вибрато (slight/wide),
палм-мьют, let ring, dead note, ghost note, акценты (обычный/сильный),
стаккато, теното, украшения (форшлаг до/на доле, мордент верхний/нижний,
тёрн и обратный, трель), тремоло-пикинг, fade in/out, натуральные и
искусственные флажолеты, тремоло-бар (как отдельный знак и как вибрато).

**Не входит:** RSE; приёмы в аккордовом редакторе/ленте (решение 6);
звук для dead slap и pick scrape — в GP они **только рисуются**, так же
делаем и мы; печать.

**Не меняется:** схема песни (остаётся 5) — все поля приёма
необязательные, старый файл и старый код читаются без потерь, как это уже
сделано с `dots`/`triplet`. Аккордовый редактор, лента, круг, ритм-рулон,
аппликатуры — без правок.

### 5.3 Данные (все поля — необязательные, на ноте партии)

```json
{ "start": 0, "dur": 1, "string": 5, "fret": 7,
  "legato": true,                                  // H/P: взятие без атаки из предыдущей ноты той же струны
  "slide": "legato" | "shift",                     // слайд В ноту (из предыдущей ноты той же струны)
  "bend": { "type": "bend"|"prebend"|"release"|"prebend-release",
            "points": [[0,0],[0.5,1],[1,1]] },     // t 0..1 от длительности, v в полутонах
  "vibrato": "slight" | "wide",
  "pm": true, "letRing": true, "dead": true, "ghost": true,
  "accent": 1 | 2,                                 // 1 — акцент, 2 — сильный
  "staccato": true, "tenuto": true,
  "grace": { "fret": 5, "onBeat": false },         // форшлаг: короткая нота перед/на доле
  "ornament": "mordent"|"upper-mordent"|"turn"|"inverted-turn",
  "trill": true,                                   // трель со следующей ступенью (лад +1 в пределах ≤24)
  "tremolo": true,                                 // тремоло-пикинг
  "fade": "in" | "out",
  "tremBar": true,                                 // тремоло-бар (знак + нырок высоты)
  "harm": { "type": "natural"|"artificial"|"pinch"|"tap"|"semi"|"feedback",
            "note": "E6" }                          // для искусственных — звучащая нота
}
```

Санитайз (как всегда — «отбросить, а не зажимать»): неизвестный тип
сбрасывается; `points` — до 8 точек, `t` зажат 0..1, `v` в −24..+24, первая
точка всегда `[0,0]` у `bend`/`prebend-release`; `accent` только 1 или 2;
`grace.fret` 0..24; `harm.note` проверяется через `noteToFrequency`;
`trill`/`tremolo`/`fade`/`tremBar` — строго `true|false`.

### 5.4 Звук: чем именно приближаем (без RSE)

| Приём | Что делаем в синтезе |
|---|---|
| Легато H/P | вторая нота без атаки: буфер играется со смещением (пропускаем щипок), громкость как у предыдущей |
| Слайд (legato/shift) | доезд высоты: `playbackRate` от частоты предыдущей ноты к своей за время слайда (shift — с атакой в начале, legato — без) |
| Бенд | кривая из `bend.points` → кусочно-линейный `playbackRate` по времени ноты (prebend — уже поднятая нота; release — спуск; prebend-release — подъём и возврат) |
| Вибрато | качание ±0.25 пт (slight) / ±0.6 пт (wide) с частотой ~6 Гц (несколько коротких линейных рампов) |
| Палм-мьют | короче (×0.35), глуше (brightness ×0.5), тише (×0.7), быстрый спад |
| Let ring | не режем по написанной длительности: звенит до следующей ноты этой струны/конца окна (потолок 6 с) |
| Dead note | очень короткий щелчок (0.05–0.08 с), без тона: низкий gain и высокий brightness |
| Ghost note | тише (×0.45) |
| Акцент / сильный | громче (×1.35 / ×1.6) |
| Стаккато / теното | стаккато режет длительность (×0.4), теното — не режет до конца написанного |
| Форшлаг | короткий (≈1/32) щипок на полтона-тон ниже/на заданном ладу прямо перед основной нотой |
| Мордент / тёрн / трель | быстрые чередования с соседней ступенью (лад ±1, ±2) в пределах длительности ноты |
| Тремоло-пикинг | повторные удары тем же ладом (≈1/16 от длительности доли) |
| Fade in/out | рампа громкости в начале/конце ноты |
| Натуральный флажолет | высота по узлу: лад 12 → +12 пт, 7 → +19, 5 → +24, 4 → +28, 3 → +31, прочее → +12 (октава) |
| Искусственный | высота из «звучащей ноты» окна параметров (`noteToFrequency`), таб показывает A.H./P.H./T.H./S.H. |
| Тремоло-бар | нырок высоты: спуск до −2 пт и возврат за длительность ноты |

| Приём | Как нарисовано |
|---|---|
| Легато H/P | дуга-лига между нотами |
| Слайд | наклонная линия между номерами ладов |

| Dead note | `x` вместо лада |

| Стаккато / теното | точка / черта под номером |

### 5.6 Клавиши (GP) и палитра

| Клавиша | Действие |
|---|---|
| `X` | dead note |
| `O` | ghost note |
| `I` | let ring |
| `[` / `]` | палм-мьют на ноту / PM на долю |
| `B` | бенд (открывает редактор кривой) |
| `H` | hammer-on / pull-off |
| `S` / `Alt+S` | legato slide / shift slide |
| `V` / `Alt+V` | вибрато slight / wide |
| `Y` / `Alt+Y` | натуральный / искусственный флажолет |
| `;` / `Shift+;` | акцент / сильный акцент |
| `Shift+1` | стаккато |
| `Shift+-` | теното |
| `N` | трель |
| `Shift+W` / `W` | тремоло-бар |
| `Shift+,` | fade in |
| `Ctrl+E` | палитра приёмов поиском (как Command Palette в GP: «palm», «bend 2») — по желанию, итерация 4 |

| 12.6.1 | Знаки и звук «динамики и штриха»: палм-мьют, let ring, dead, ghost, акценты, стаккато/теното, fade | **сдана — 0.624**: новый сьют `b12-effects.js` (57/57), часть 1 |

(R6/R1). Кирпич закрывается только после четвёртой итерации.

**Реализационные уточнения итерации 1 (0.624).**

- **Полки знаков.** Струны на стане стоят через 9 единиц viewBox, а фишка
  ноты занимает 16 — внутри стана знак лёг бы на соседнюю струну. Знаки
  вынесены за линейки (в GP линия PM тоже идёт над табом) и живут полками:
  сверху — пунктир PM, подписи PM и L.R.; снизу — артикуляция, акценты,
  стрелки fade. Запас `viewBox` считается по РЕАЛЬНО занятым полкам, поэтому
  стан без знаков остаётся геометрией 12.3.
- **Отличие от GP по клавише теното:** `Shift+T` вместо `Shift+−` — `_` с
  0.621 значит «длиннее» (решение пользователя). Экранный знак тот же «—».
- **Взаимоисключения:** стаккато ↔ теното, fade in ↔ fade out снимают друг
  друга (в GP это знаки одного смысла).
**Реализационные уточнения итерации 4 (0.627).**

- **Натуральный флажолет** считается от ОТКРЫТОЙ струны по узлу лада
  (12 → +12 пт, 7 → +19, 5 → +24, 4 → +28, 3 → +31, прочее → +12), а не от
  прижатого лада: флажолет на 12-м ладу звучит как нота 12-го лада, на
  7-м — как нота 19-го.
- **Искусственный флажолет** без читаемой «звучащей ноты» не ставится ни
  нотой, ни чтением файла: знак без высоты показывал бы приём, которого не
  слышно. Тип и нота запоминаются палитрой и переходят к следующим нотам.
- **Украшения играются сдвигом `playbackRate`** (±полутон), а не соседним
  ладом: приём работает и на границе грифа; тёрн/мордент не снимают знаки
  ноты, трель и тремоло-пикинг собираются одним планом ударов
  (`partStrokePlan`).
- **Форшлаг** — короткий щипок (≈1/32) перед нотой; «на доле» основная нота
  сдвигается на длину форшлага. Клавиша `G` (в GP8 отдельной клавиши нет),
  `Alt+G` — «на доле», «форшлаг N» в поиске задаёт лад.
- **Тремоло-бар приоритетнее слайда, но уступает бенду**: если у ноты есть
  кривая бенда, высоту ведёт она.
- **Dead slap и pick scrape** — знаки без звука: подписаны `slap` и
  `scrape` над станом (глифы GP — фирменные картинки).
- **Знаки живут полками над станом** (флажолет, трель, украшение, форшлаг,
  слэп, скребок): номер лада занимает 16 единиц при шаге струн 9, поэтому
  внутрь стана знак не пускается — правило 12.6.1. Запас вокруг стана
  считается по фактически занятым полкам.

**Реализационные уточнения итерации 3 (0.626).**

- **Окно кривой** живёт вне списка дорожек (`#partsBend` рядом с `#partsBody`):
  перерисовка табулатур его не сносит. Шаг высоты точки — четверть тона,
  точек не больше восьми, первую точку не сдвинуть и не убрать.
- **Мышь и модель:** во время перетаскивания меняются только кружок и линия
  (правило 60 fps), модель — один раз по `pointerup`, одной командой Store.
- **Вибрато после бенда** качается вокруг ПОДТЯНУТОЙ высоты (центр — значение
  последней точки кривой), а не вокруг написанной.
- **Бенд приоритетнее слайда** на той же ноте: кривую высоты ведёт кривая
  бенда; легато с бендом сочетается (прижим лада + подтяжка).
- **Знак на табе** — стрелка направления и величина долями тона (`full`,
  `½`, `¼`, `1¼`), своя полка над станом; полка тратится, только если бенд
  есть в системе.

**Реализационные уточнения итерации 2 (0.625).**

- **Легато высоту не тянет.** Хаммер ставит палец на лад сразу: голос берёт
  свой буфер со смещением 20 мс, но `startRate` не меняет. Наклон высоты —
  только у слайда (в GP у ноты с H/P наклона тоже нет).
- **Тремоло-пикинг — серия ударов**, а не отдельный голос: планировщик
  повторяет щипок каждую 1/16 длительности доли (шаг считается в долях
  четверти, поэтому 6/8 и 4/4 звучат одинаково), потолок — 24 удара.
  В предпросмотре тремоло играет один удар — там нужен знак, а не серия.
- **Кривая высоты — чистая функция** `partRateCurve`: планировщик применяет
  её к `playbackRate`, а тесты проверяют без звуковых узлов.
- **Слой голоса.** В `pluckString` добавлены необязательные `fadeIn`,
  `fadeOut`, `releaseAt`/`releaseTime` (обрыв с реально звучащей громкости) и
  `skipAttack` (смещение в буфере — понадобится легато в 12.6.2). Без
  параметров поведение прежнее.

### 5.8 Критерии приёмки

1. Любой приём ставится с клавиатуры и из палитры, снимается повторным
   нажатием; вся правка — одна команда Store и один шаг `Ctrl+Z`.
2. Знак виден на табе в том виде, что описан в 5.5, и **на звук влияет**
   (кроме dead slap / pick scrape — они только знаки, как в GP).
3. Файл: приёмы уезжают в песню необязательными полями, песня старого
   формата грузится без изменений, испорченные значения отбрасываются.
4. Курсор, ввод цифрами, длительности и все операции 12.2–12.3 работают
   ровно как раньше (регресс-проверки `b12-input.js`, `b12-parts.js`,
   `b12-tracks.js` зелёные).
5. Аккордовый редактор, лента, круг и ритм-рулон не меняются.

## 6. Кирпич 12.5 «Микшер» — разведка GP8 (2026-10-13)

Пользователь перед микшером сказал «изучи гтп»: где в Guitar Pro живут
громкость, панорама, mute/solo. Изучено по официальной документации GP8
(Global View, Automations, Tuning Settings) и по обзорам.

### 6.1 Что в GP8 есть (факты, на которые опираемся)

- **Микшер — это Global View**, панель внизу окна (F8 или кнопка в
  тулбаре). Она одновременно и микшер, и обзор партитуры: клик по такту
  переводит туда курсор, можно выделять несколько тактов и дорожек.
- Колонка дорожки: имя, перестановка «выше/ниже», «глаз» (показывать в
  мультидорожном виде), **Mute**, **Solo**, **Focus/Unfocus**, слайдер
  **громкости**, ручка **панорамы**, **эквалайзер**, а рядом с громкостью и
  панорамой — кнопка **автоматизации** (буква A).
- **Мастер-полоса**: ручка **focus** (поднять/понизить текущую дорожку, не
  трогая её слайдер), общая громкость и панорама, mute/solo мастера.
- **Focus ≠ Solo**: solo глушит остальные дорожки, focus просто приглушает
  их, сохраняя ансамбль слышимым.
- **Автоматизации** (F10): громкость, панорама, темп — точками по времени;
  у каждой точки «constant until next point» или «progressive to next
  point». Есть «Remove automations».
- Звук дорожки (тембр, эффекты, эквалайзер, струнные настройки) живёт **не
  в микшере**, а в Track Inspector справа.
- Значения микшера — часть песни (файла), а не только сессии.

### 6.2 Каподастр в GP8

- Каподастр — **свойство дорожки**: Track Inspector → Musical notation →
  Tuning → шестерёнка → **Capo** (по всему ладу) и **Partial capo**
  (частичный: на одну или несколько струн; номера ладов **абсолютные**,
  частичный каподастр независим от основного; поставленный ниже основного —
  не действует). Оба можно ставить одновременно.
- При смене строя/каподастра GP спрашивает: **Keep fingering** (ничего не
  транспонируется, табулатура остаётся как была) или **Adjust fingering**
  (аппликатура пересчитывается так, чтобы **высоты нот остались прежними**).
- В инспекторе видно «transposition tonality» — например, при каподастре на
  2-м ладу: «C played as D».
- Общая настройка File → Stylesheet → System & Staves: «capo and shifted
  tunings impact standard notation» — влияет ли каподастр на нотный стан.
- На стане каподастр показан значком/надписью над системой.

**Ранее принятое решение пользователя:** каподастр у нас — «как в GP,
пересчётом позиций» (аналог **Adjust fingering**: числа на табах
пересчитываются, высоты нот остаются записанными), а не «сдвигом звука».
### 6.3 Ответы пользователя (допрос R8 2026-10-13)

| # | Вопрос | Ответ |
|---|---|---|
| 1 | Где живёт микшер | **Полоса в окне «Партии»** — панель под табулатурами, как Global View в GP |
| 2 | Состав | **Совсем как в GP**: громкость, панорама, M/S, focus, эквалайзер и автоматизации (разнесены по итерациям 12.5.1–12.5.3) |
| 3 | Каналы | **Партии + «Песня» + мастер** (громкость и mute у мастера) |
| 4 | Каподастр: крайний случай | **Поднимать на октаву** аналогом GP «Adjust fingering», показав перед применением список затронутых нот |
| 5 | Каподастр — для кого | **И у партий, и у песни** (надпись «играть с каподастром N» над аккордами, аппликатуры не пересчитываются) |

| # | Итерация | Что входит | Статус |
|---|---|---|---|
| 12.5.1 | Полоса каналов | M/S/focus, громкость и панорама у «Песни», дорожек и мастера; значения в файле песни | **сдана — 0.628**: сьют `b12-mixer.js` (38/38) |
| 12.5.2 | Эквалайзер | Трёхполосный EQ на канал (низ/середина/верх), «по нулям» — не пишется в файл | в работе |
| 12.5.3 | Автоматизации | Громкость и панорама точками по времени, «держать до следующей» / «плавно к следующей» (F10 в GP) | ожидает |
| 12.5.4 | Каподастр | Свойство дорожки и песни, окно с Keep/Adjust, пересчёт позиций, знак на стане | ожидает |

**Реализационные уточнения 12.5.1 (0.628).**

- **Solo глушит «Песню»** тоже: в GP solo глушит все остальные дорожки, а
  аккомпанемент у нас — такая же дорожка микшера. Это записано тестом.
- **Focus — настройка прослушивания**, не данные песни: в файл не пишется,
  при загрузке песни сбрасывается в нейтраль (100 = без надбавки).
- **Протяжка ползунка** идёт через временный `mixerPending`: во время
  движения меняется только звук, модель — одна команда Store по отпускании
  (правило 60 fps и один шаг `Ctrl+Z`).
- **Карточки каналов не пересобираются** при перерисовке окна партий —
  протяжка не теряет элемент, по которому тянут.
- **Файл пишет только неумолчательные значения** (`mix` у партии и песни),
  поэтому обычная песня не растёт; схема остаётся 5.
