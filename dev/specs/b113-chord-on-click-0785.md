## Что сообщил владелец

> «аккорд сменяется раньше клика»

Это продолжение принятой 0.784: владелец подтвердил, что переходы звучат хорошо, но после укорачивания захода всё равно слышит смену раньше щелчка. Уточняющие ответы: **≈⅓ доли раньше** (`third`), **на каждом аккорде** (`everywhere`), вариант **`on_click` — «слайд на щелчке и после него»**, оформление **`full`**.

**Вывод:** часы не сбились — граница аккорда и сильный щелчок совпадали ровно (0 мс, это проверял ещё тест 0.784). «Pad опережает» — это **само устройство перехода**: он целиком лежит ДО щелчка. 0.784 укоротил заход с 350 до 167 мс, но **не перенёс** его. В прошлом раунде владелец выбрал `shorter` («короче»), а не «поставить на щелчок» — теперь стало ясно, что одной длины недостаточно.

## Что сделано

**Одна правка по существу — `keyboard-audio.js`, `padStep()`.** Раньше `end = start + dur` (граница = щелчок) и все три события перехода ставились на отрезок `[end − lead, end]`:

```js
padGlide(v, p.to, end - lead, end);                       // изгиб высоты
padRelease(v, end - lead, end);                          // уход старых нот
padVoice(ctx, target, p.to, end - lead, end, level, lead); // наплыв новых нот
```

Теперь `lead` считается раньше, вводится `boundary = start + dur` и **`end = boundary + lead`**. Те же самые три вызова автоматически оказываются на отрезке **`[щелчок, щелчок + lead]`**: старый аккорд держится до удара, на ударе начинается плавный переход, новый аккорд приходит через ⅓ доли после него. Голоса живут на `lead` дольше ячейки — иначе Web Audio оборвал бы их прямо на щелчке; следующая ячейка продлевает их штатным `padExtend()`, лишних источников нет (проверено тестом). Подсветка звучащих клавиш 0.763 оставлена в рамках ячейки (`dur`, а не `end − start`).

| | 0.784 | 0.785 |
|---|---|---|
| начало изгиба | 1,833 с (**−167 мс**) | **2,000 с (0 мс)** |
| конец изгиба | 2,000 с | 2,167 с |
| старт новых нот | 1,833 с | **2,000 с** |
| начало гашения пустой ячейки / конца песни | за ⅓ доли до границы | **на границе** |
| приход нового аккорда | на щелчке | через ⅓ доли после щелчка |

**Не изменилось:** длина перехода `lead = max(0,05; min(⅓ пульса; 0,35 с; 20 % ячейки))` из 0.784, пульс составного размера (пунктирная четверть в 6/8), S-кривая из 33 точек по `playbackRate`, предел 7 полутонов, `hold` общих тонов, перетекание между секциями, реальный `padNext` от плеера (0.783), часы метронома `metronomeGridKey` (0.784), `findNextEvent`, логика 0.775, мгновенный Стоп, экспорт MIDI/GPX/GP5, пианино/Rhodes/орган, миграции (нет). Имя `lead` сохранено для совместимости API и тестов — теперь это **длина перехода**, а не опережение; комментарии в трёх файлах уточнены.

**Осознанный риск:** новый аккорд приходит **чуть позади удара** (≈167 мс при 120 BPM). Это прямое следствие выбранного варианта: нельзя одновременно держать весь переход после щелчка и получить новый аккорд точно на щелчке. Если на слух это ощущается как «pad запаздывает», следующий шаг — вариант «середина перемены на щелчке» (половина изгиба до, половина после, цена M–L), который в 0.785 **не делался**. Длину ⅓ доли после удара можно укоротить отдельно по слуху.
