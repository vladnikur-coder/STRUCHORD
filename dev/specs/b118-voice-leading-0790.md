# B-118 · 0.790 — голосоведение по всей песне (prev через границы секций)

Дата: 2026-11-04. Ветка: `arena/bf99fe44-struchord`. Версия: 0.790 (`ver 0.790` + `struchord-v790` парой, R7).

## Контекст и опрос R8 (ответы владельца)

Кирпич 4 очереди B-39 «улучшение расположений» (`dev/specs/piano-voicing-review.md`,
следующий пункт после обращений — голосоведение). Опрос R8, 2026-11-04:

- **Область:** «по всей песне» — включая границы секций и повторы.
- **Цель:** минимум суммарного движения нот правой руки + лёгкий штраф за уход
  от середины клавиатуры (то, что уже считает `chooseLinked`: `motionCost(prev,v) + |center−target|·0.01`).
- **Защита:** ручные `exactNotes`/индекс варианта побеждают; старые песни без
  галочки `linkedVoicings` — прежнее поведение; у новых песен галочка включена
  по умолчанию (как в 0.720/0.780).
- **Формат:** полный комплект сразу, версия 0.790; read-only замер перед кодом;
  push только в arena-ветку. Резюме подтверждено `final=yes`.

## Read-only замер (до кода)

`linkedSelection(trackId,cell)` в `STRUCHORD.html` (модуль keys, ~стр. 32573):
кэш строился на ключе `trackId+':'+secId` — **на одну секцию**, `prev:null` в
начале каждой секции. Следствие: первый аккорд новой секции выбирался только
по центру руки (`prev=null`), связь через границу секций отсутствовала.
`dev/prototypes/voice-leading.js` (motionCost DP) существует как прототип, в
HTML — своя копия `motionCost` (~стр. 32238, RH-only `slice(1)`, entryCost 12).

## Что изменилось

Патч `dev/tools/patch-b118-voice-leading-0790.py` (5 якорей в `STRUCHORD.html`):

1. Кэш `linkedSelection` — ключ `String(trackId)` (вся песня); события собираются
   со **всех** секций в порядке документа (`sections.forEach(...)`), в запись
   события добавляется его секция (`{sec:sec2,...}`).
2. Основной цикл: ключ события из его секции — `var key=(e.sec&&e.sec.key) || currentKey()`.
3. Fallback за пределом 2048: ключ из секции дальней ячейки `(far.sec&&far.sec.key)`.
4. Комментарии обновлены («обход по всей песне», «длинная песня после 2048»).
5. UI-подпись: «Голосоведение внутри секции» → «Голосоведение по всей песне».

Плюс R7: `ver 0.789→0.790` в шапке HTML, `struchord-v789→v790` в `sw.js`.

## Семантика

- `prev` (последний выбранный набор нот) перетекает через границы секций:
  последний аккорд секции A продолжает первый аккорд секции B.
- **Повторы и скачки (D.S./Coda) не раскрываются.** Повтор секции получает тот
  же выбор, что и первый проход (кэш per-track на всю песню, детерминированно).
  Звук/превью/экспорт/схема идут через тот же `linkedSelection` — поэтому
  совпадают. Это осознанный выбор: раскрытие прыжков дало бы разный выбор для
  звука и для схемы.
- Ручной приоритет сохранён: `exactNotes` ячейки и ручной индекс варианта
  (`voicings['v:'+chord]` / `voicings[cell]`) побеждают и становятся `prev`.
- Лимит 2048 событий на песню и fallback (независимый выбор без истории)
  сохранены; за пределом лимита схема/звук/экспорт по-прежнему совпадают.
- Старые песни: без `linkedVoicings` функция возвращает `null` сразу —
  прежнее поведение, миграций нет.
