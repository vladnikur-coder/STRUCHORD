# B-122 · Фоновая аудиодорожка и синхронизация по точкам (как в Guitar Pro)

**Статус:** R8 final=yes (2026-11-08) — волна `0.811` (`struchord-v811`).
**Бэклог:** №30 (`B-122`).

## 1. Решения владельца (R8, 2 раунда, 2026-11-08)

1. **`sync_mode = sync_points_gp`:** загрузка аудиофайла (`MP3 / WAV / M4A / OGG / FLAC / AAC / WEBM`), отрисовка звуковой волны, установка старта 1-го такта и перетаскиваемых **точек синхронизации (Sync Points)** на границах тактов с автоматическим расчётом локального BPM между соседними точками + изменение общей скорости воспроизведения без смены высоты тона (`preservesPitch`).
2. **`tempo_authority = sync_is_100pct_speed_slider`:** на скорости **100%** аудио играет в своей родной скорости (`playbackRate = 1.0`, без ресемплинга и искажений), планировщик STRUCHORD идёт строго по точкам на волне (показывая текущий/средний расчётный BPM), а отдельный регулятор скорости **50%–150%** синхронно тянет и аудио (`preservesPitch = true`), и планировщик STRUCHORD.
3. **`point_anchor = bar_number_gp8`:** каждая точка хранит `{ bar, time }` — 0-индексный номер развёрнутого такта и секунду в аудиофайле. При редактировании структуры песни точки никогда не удаляются и остаются на своих пиках волны.
4. **`ui_placement = mixer_plus_drawer`:** блок фонового аудио в микшере **«Дорожки»** (выбор/замена/удаление файла, громкость, `M`, `S` в общей матрице Mute/Solo с гитарными и клавишными дорожками) + **раскладная панель волны и сетки тактов** (зум, прокрутка, расстановка/перетаскивание/снятие точек синхронизации, клик-перемотка, регулятор скорости 50%–150%), доступная и в Редакторе, и в Ленте.
5. **`storage_scope = idb_plus_opt_embed` + лимит `25 МБ` + перенос карты темпов в GP5/GP6/MIDI:**
   - Лимит размера файла: **25 МБ** (`25 * 1024 * 1024` байт).
   - В браузере бинарные данные хранятся в `IndexedDB` (`struchord-backing-audio-v1`, переживают перезагрузку и офлайн, уборка неиспользуемых блобов при удалении песен), а в `localStorage` и истории Undo/Redo лежат только лёгкие метаданные и `syncPoints`.
   - При экспорте `.struchord` (если у песни есть фоновое аудио) — выбор: **«Вшить аудио внутрь файла»** или **«Только разметка синхронизации (лёгкий файл)»**.
   - При экспорте в **GP5 / GP6 (GPX) / MIDI** — рассчитанные по точкам темпы тактов переносятся в тактовую карту темпов (`bar.bpm` / MIDI tempo events), а в отчёт экспорта пишется пометка, что сама фоновая аудиозапись не переносится в формат.
6. **`playback_behavior = unrolled_follow_all`:** сетка тактов строится по развёрнутой форме песни (с учётом повторов квадратов и секций `×N`); перемотка и старт с любой позиции синхронно переводят аудио и планировщик в точную секунду; при включённом предсчёте звучит реальный затакт записи до стартового такта (если он есть в аудио), а недостающая часть предсчёта идёт под метроном.

## 2. Математическая модель времени

- Развёрнутый обход песни (`findNextEvent` с `{ noLoop: true }`) даёт последовательность событий и развёрнутых тактов `b = 0 .. B-1`, где каждый такт с размером `numerator/denominator` содержит `quarters(b) = numerator * (4 / denominator)` четвертных долей, а накопленная четвертная позиция начала такта `b` равна `Q(b)`.
- Точки синхронизации `P_0, ..., P_{k-1}` упорядочены строго возрастающе по такту и времени (`P_i.bar < P_{i+1}.bar`, `P_i.time < P_{i+1}.time`).
- Кусочно-линейное отображение четвертной позиции `q >= 0` в секунду аудио `T(q)`:
  - `k = 0`: `T(q) = q * (60 / baseBpm)`.
  - `k = 1` (`P_0 = { bar: b_0, time: t_0 }`): `T(q) = t_0 + (q - Q(b_0)) * (60 / baseBpm)`.
  - `k >= 2`: на сегменте `[Q(b_i), Q(b_{i+1})]` линейная интерполяция `t_i + (q - Q(b_i)) / (Q(b_{i+1}) - Q(b_i)) * (t_{i+1} - t_i)` (локальный темп `60 * (Q(b_{i+1}) - Q(b_i)) / (t_{i+1} - t_i)` BPM); левее `P_0` — экстраполяция темпом первого сегмента, правее `P_{k-1}` — темпом последнего сегмента.
- Для события `[q_start, q_end]` при коэффициенте скорости `speedRate` (`0.50 .. 1.50`):
  - `evStart = audioZeroCtxTime + T(q_start) / speedRate`
  - `evEnd = audioZeroCtxTime + T(q_end) / speedRate`
  - `dur = evEnd - evStart` (без накопления ошибки округления от такта к такту)
  - `effectiveBpm = 60 * (q_end - q_start) / dur` — передаётся в гитарный бой, клавишный планировщик, табы, метроном и Ленту.

## 3. Границы производительности и безопасности

- Во время `pointermove` перетаскивания точки синхронизации на волне перерисовывается **только `<canvas>`** через `requestAnimationFrame` — без вызовов `render()`, мутаций `innerHTML` и синхронного layout reflow; запись в модель и `captureHistorySnapshot()` выполняется один раз на `pointerup`.
- Файлы `> 25 МБ` отклоняются до чтения в память с понятным тостом.
- Обычные песни без фонового аудио сериализуются байт-в-байт идентично прежним версиям (`backingTrack` опускается).

## 4. Sync Editor, итерация 0.814

По запросу «сделать удобнее, руководствуясь успешным примером Guitar Pro» добавлен авторский workflow, опирающийся на паттерны [alphaTab Media Sync Editor](https://github.com/CoderLine/alphaTab/blob/develop/website/docs/guides/media-sync-editor.mdx) и [Sync Points at runtime](https://github.com/CoderLine/alphaTab/blob/develop/website/docs/features/play-sync/sync-points-at-runtime.mdx), при этом R8-модель `{bar,time}` и привязка к границам развёрнутых тактов сохранены:

- Waveform показывает все маркеры развёрнутых тактов (включая проходы повторов), нумерацию и долевые риски; playhead виден поверх волны.
- Перетаскивание любого тактового маркера превращает его в Sync Point или двигает уже существующую точку; время ограничено соседними точками. Двойной щелчок по маркеру переключает внутренний Sync Point; начальный и конечный якоря нельзя удалить.
- Клик по волне перематывает аудио и выбирает ближайший такт. Фокусируемая волна поддерживает стрелки для перехода по тактовым маркерам и `Shift+стрелки` для перехода между Sync Points; в списке точек `Alt+стрелки` двигают выбранную точку на 10 мс, `Shift+Alt+стрелки` — на 100 мс. Числовое поле даёт точность 1 мс.
- Автосинхронизация создаёт точки начала, конца и смены темпа (позиции внутри диапазона начала–конца оцениваются по длительностям тактов/темпам песни); для новой загрузки набор создаётся автоматически, а ручной сброс доступен кнопкой «Автосинхронизация».
- Undo/Redo остаётся на общей истории песни: перетаскивание или числовое изменение фиксируется атомарно.

**Сознательно не переносим без отдельного решения:** GP8/alphaTab может хранить положение внутри такта (`barPosition`) и отдельные привязки к проходам (`barOccurrence`). STRUCHORD пока оставляет точки на границах тактов и представляет повторы развёрнутым индексом `bar`, как было согласовано в R8.
