# B-39 · итерация 0.795 — якорь автоаккомпанемента = ячейка + ползунок «Насыщенность» + чистка UI

Дата: 2026-11-05. Ветка: `arena/8313d77b-struchord`. Версия: 0.795 (`ver 0.795` + `struchord-v795`, R7).
Бэклог: строки №21 (якорь-ячейка) и №22 (ползунок насыщенности) — одна итерация B-39, обе «в работе».

R8-резюме подтверждено владельцем `final=yes` (2026-11-05), видео `uploads/акк.mov` (на main) просмотрено.

## Решения владельца

1. **Якорь — ячейка (№21):** автоаккомпанемент изначально берёт конкретное расположение ячейки
   (приоритет `exactNotes` → `voicings[cell]` → `v:<аккорд>` → авто), новые ноты накидываются поверх
   «как пианист». При смене обращения в ячейке звучание авто на этой ячейке меняется от этого обращения.
2. **Ползунок «Насыщенность» 0–100 (№22)** — единый орган управления вместо связки опций.
   Семантика подтверждена видео: в припеве (pop, 120 BPM) блоковые удары играют правой рукой
   4 ноты с корнем, удвоенным октавой вверх (C4 E4 G4 C5 + бас) — это именно насыщение.
   На минимуме — простое трезвучие; выше — октавные удвоения корня/квинты; на максимуме — плюс
   акцент 13/9 в конце такта и плотность по роли секции.
3. **Чистка UI:** убрать тоггл «Плотно|Широко» (`#b39KeysDensity`), «Выделять 13/9 в конце такта»
   (`#b39AutoEndAccent`), «Держаться выбранной формы аккорда» (`#b39AutoFollowShape`),
   «Сбросить выбор позиции» (`#b39LinkedReset`), отдельную галочку «Плавные обращения для всей дорожки»
   (ей управляет общая галочка голосоведения). Остаются: стрелки ‹ › обращений, галочка
   голосоведения, жанр, swing. Данные старых песен не мигрируются — UI прячется, значения читаются как есть.
4. Порядок: сначала эта спека, затем этапы одной волны патчами из `dev/tools/` (HTML руками не правим).

## Диагноз (read-only, 2026-11-05)

Источники «насыщенных» форм в автоаккомпанементе:
- генератор notes-v1 (`planSequence`, STRUCHORD.html ~51013):
  `preferDoubling = role==='chorus' && chord.beats>=2 && bpm<=140` — в припеве разрешает
  октавное удвоение корня/квинты (`candidates()` ~50948, `doubleBonus=12`). Подтверждено видео:
  припев, C, бас C3, правая рука C4 E4 G4 C5.
- role-факторы: `ROLE.chorus=1.16` (плотность), `ROLE_LEVEL.chorus=76`.
- блоковый авто (`keyboard-accompaniment.js`): `applyExtensionAccent()` (~803) — 13/9 сверху на
  последнем аккорде такта (0.789/0.793, гейт `endAccent`).
- fallback `voicingFor()` (keyboard-audio.js ~310): всегда удвоение корня +12.

Текущие разрывы:
- при **выключенном** голосоведении звуковой путь читает только `v:<аккорд>` —
  `voicingProvider` вызывает `variantIndex(trackId, chord, null)` (cell=null), per-cell
  `voicings[cell]` игнорируется (STRUCHORD.html ~33515, ~32724);
- стрелки ‹ › пишут `v:<аккорд>` (`setVariantIndex` → `setVoicingForChord`) — меняют все ячейки
  с этим аккордом, а не выбранную;
- toggl «Плотно|Широко» = раздвижение теми же нотами (0.793), а не насыщение.

## План этапов

### Этап 1 — якорь-ячейка (№21), цена M
- `voicingProvider` (и `selectedShape`, и звуковые вызовы в keyboard-audio.js 826/892/941):
  передавать реальный `cell` в `variantIndex`, чтобы читался `voicings[cell]`; приоритет
  `exactNotes > voicings[cell] > v:аккорд > авто`.
- `setVariantIndex` при выбранной ячейке пишет per-cell (`voicings[cell]`), `v:аккорд` не трогаем.
- `linkedSelection` уже учитывает per-cell — выровнять приоритеты одинаково.
- Звук, превью, подсветка, экспорт — один путь (как сейчас).

### Этап 2 — ползунок «Насыщенность» (№22), цена L
- Новое поле дорожки/настроек авто, например `track.saturation` (0–100, умолчание 50 для новых,
  у старых песен поле отсутствует = прежнее поведение).
- Ползунок управляет: `preferDoubling` (notes-v1; например насыщенность ≥ 60 + роль/темп),
  `endAccent` (блоковый авто), плотность по роли (масштаб ROLE-факторов).
- Тоггл «Плотно|Широко» из UI убирается; список вариантов со «широкими» слотами остаётся
  внутри (fallback 2048), но UI его не предлагает.

### Этап 3 — чистка UI
- Скрыть: `#b39KeysDensity`, `#b39AutoEndAccent`, `#b39AutoFollowShape`, `#b39LinkedReset`,
  отдельную галочку «Плавные обращения…» (51780) — голосоведение управляет и linkedVoicings.
- Данные старых песен (`endAccent`, `followShape`, `linkedVoicings`, `voicings`) не мигрируются и
  продолжают читаться; просто UI их не показывает.

## Что не меняется
- жанры, swing, стрелки обращений, галочка голосоведения;
- старые песни без per-cell данных звучат как раньше (R10/R12);
- `voicingsVersion` и гейты 0.794 не ломаем.
