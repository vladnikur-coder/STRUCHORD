# B-39 · насыщенность = богатство звука, плавные кривые 0.803

**Статус: R8 final=yes (2026-11-08) — волна в работе. Слуховая приёмка 0.802 пройдена владельцем.**
Дата обсуждения: 2026-11-07, финал 2026-11-08. Бэклог: №27 (плотность уходит в №28). Версия волны: 0.803 (`struchord-v803`, R7).

## Решения владельца (зафиксированы, R8-обсуждение 2026-11-07)

1. **Семантика «А — богатство звука»:** ползунок управляет только вертикалью —
   сколько нот звучит одновременно в аккорде: октавные удвоения корня/квинты,
   надстройки 9/13 сверху, ширина. Горизонталь (плотность атак) из семантики
   убирается; вернётся пользователю ползунком «Интенсивность» (бэклог №28).
2. **Плавные кривые** вместо жёстких порогов 60/80 — без мёртвых зон,
   детерминированные по seed.
3. **Единые правила для всех жанров** — жанровой маршрутизации нет (явный отказ
   владельца: предсказуемость важнее идиоматичности).
4. **Панель зеркалит слух:** `saturateNotes` использует те же вероятности,
   что и генератор, — что слышно, то и в аппликатуре.
5. Старые песни без поля и ручные рисунки (`exactNotes`/`voicings[cell]`)
   не трогаются.

## Кривые (предложение, ждёт R8 final)

Форма — smoothstep `t²(3−2t)` (медленный старт, быстрый середина, мягкий
финиш); окна из бэклога №27:

- **P_удв(sat) = smoothstep((sat−40)/50)** — 0 ниже 40, 1 выше 90; P(50)≈0,10
- **P_139(sat) = smoothstep((sat−70)/30)** — 0 ниже 70, 1 выше 100; P(50)=0

Детерминизм:
- генератор: решение по хэшу `(seed, chordIndex)` — при сработке включаются
  doubled-кандидаты (механика `doubleBonus` без изменений);
- блоковый авто: акцент 13/9 на последнем аккорде такта по хэшу `(seed, такт)`;
- панель/звук: `saturateNotes` — по хэшу `(trackId, chordName)`: одинаковые
  аккорды обрабатываются одинаково (консистентность вида и звука).

Охранные условия сохраняются: удвоение только при `chord.beats>=2` и
`bpm<=140`; добавленные сверху ноты — только при `spanOk` (≤ 15) и влезании
в диапазон дорожки.

Слышимые следствия отката плотности (решение владельца): у песен, где ползунок
стоял ниже ~62, новые генерации станут чуть плотнее (множитель уходил до
0.75), выше ~62 — чуть реже (до 1.15); уже сохранённые партии не меняются;
осознанное управление плотностью вернётся в №28.

## Открытые вопросы — закрыты R8 final 2026-11-08

1. **Нижняя половина (0–40): «беднее нормы» — шеллы (решение владельца).**
   При sat<40 авто-вокализг прореживается до 2-нотного шелла в правой руке
   (бас остаётся): корень + 7-я, если ступень есть в аккорде, иначе корень +
   3-я; для аккордов без терции (sus) — корень + 5-я. Вероятность
   P_шелл(sat) = smoothstep((40−sat)/40): 0 при 40, 1 при 0. Вся шкала 0–100
   живая. Охрана: прореживание не оставляет правую руку пустой — если ноты
   определить нельзя, возвращаем исходные.
2. **Дефолт 50: окно удвоения 40→90 (решение владельца).** P(50)≈10% — новые
   песни на дефолте чуть богаче, чем в 0.795–0.802 (тогда на 50 удвоений не
   было вовсе). Окно 13/9 остаётся 70→100, P(50)=0.
3. Слуховая приёмка 0.802 пройдена; мерж в main до старта волны.

## Как построено (as built, 2026-11-08)

- `planSequence` получил `seed` (передаётся из `buildSequence`); решения
  удвоения/шелла — `satHash(seed, i, salt)` против `satSmooth(...)`:
  удвоение `smoothstep((sat−40)/50)`, шелл `smoothstep((40−sat)/40)`.
  Выбор между шеллом корень+3-я и корень+7-я у септаккордов отдан стоимости
  DP (обе формы — кандидаты), а не жёсткому приоритету; у аккордов без
  терции (sus) базовый срез даёт корень+5-ю. Правая рука не пустеет:
  при единственной ступени шелл-бонус просто не срабатывает.
- `candidates(..., preferShell)`: при `count===2` добавляет вариант
  `[pcs[0],pcs[3]]` (корень+7-я) для септаккордов; `shellBonus` =
  стоимость пропуска + 16 — шелл решительно выигрывает у полного
  голосоведения, когда вероятность сработала.
- Плотность: `strength = ROLE[role]·corpusDensity` — множитель
  `0.75+sat/250` удалён (sat-путь стал совпадать с absent-путём и
  прототипом).
- `saturateNotes`: вложенные `satCurveBetween`/`satHashStr` (FNV-1a);
  решение по `(trackId, chordName)` — одинаковые аккорды насыщаются
  одинаково, панель зеркалит звук.
- Блоковый авто: `endAccentEnabled` возвращает вероятность
  `smoothstep((sat−70)/30)` (legacy-булевы сохранены); `applyExtensionAccent`
  решает по тактам хэшем `accentRand(eaBase + '#' + номер такта)`, где
  `eaBase = trackId|secId|sq` — стабильно для песни и живо между квадратами.
- Фикстуры тайминга/динамики насыщенность не параметризуют — не тронуты
  (проверено grep и прогонами 0771/0772).
- Тесты: переписаны `b39-saturation-0795.js` (контракт кривых, якоря
  0/40/100, монотонность, живая шкала), `b39-saturation-panel-0797.js`
  (якоря, «выросшее не убывает», детерминизм по (дорожка, аккорд)),
  2 строки в `b39-review-fixes-0793.js`; новый
  `dev/tests/b39-saturation-smooth-0803.js`: сетки атак обеих рук
  идентичны при sat 0/40/100 (ритм не тронут), вертикаль растёт
  48→52→56 нот, детерминизм, кривая endAccent, R7-пара.
  `b39-hiphop-genre-0802.js` переведён на динамический R7-контракт.

## Критерии приёмки

- Каждое движение ползунка в рабочем диапазоне слышно как изменение богатства
  вертикали — без мёртвых зон и рывков (порогов).
- Плотность атак (атак/такт), groove-семейство и длина нот не меняются от
  ползунка (тест на фикс. seed: число атак константно при любом sat).
- Старые песни (без поля) и ручные рисунки звучат как раньше.
- Панель и звук согласованы: одинаковые аккорды — одинаковое решение.
- Слуховая проверка владельцем: на дефолте 50 — как решит R8 (вопрос 2);
  на 100 — сочный припевный звук из видео 0.795 (C4 E4 G4 C5 + бас + 13/9).
