# Промпт: редизайн редактора аппликатур (B-78)

Задача: полностью переработать ВИЗУАЛЬНЫЙ дизайн модального редактора
аппликатур STRUCHORD, сохранив ВЕСЬ функционал 1-в-1. Текущий редактор
пользователь описал как «массивный, некрасивый, не соответствует дизайну
приложения». Нужен аккуратный, лёгкий, «родной» приложению вид.

Это НЕ переписывание логики подбора/сохранения — только слой
представления (разметка модалки, стили, компоновка, гриф-SVG,
микровзаимодействия). Вся модель, сохранение, подбор, идентичность
баррэ (B-74/B-75) и массовое применение (B-76) остаются как есть.

---

## 1. Язык дизайна приложения (ориентир)

Брать ТОЛЬКО из существующих CSS-переменных (12+ цветовых схем + тёмная
тема должны работать без правок):

- Поверхности: `--color-surface`, `--color-surface-hover`,
  `--color-neutral-bg`, `--color-body-bg`.
- Текст: `--color-text-primary`, `--color-text-secondary`,
  `--color-text-tertiary`.
- Акценты: `--color-ink` (главное действие), `--color-accent` (вторичный
  акцент), `--color-danger` (опасное/приглушить), `--color-success`.
- Границы: `--color-border-light`, `--color-border-medium`.
- Гриф: `--fingering-nut-line`, `--fingering-fret-line`,
  `--fingering-string-line`, `--fingering-fret-number`,
  `--fingering-open-marker`.
- Форма: скругления как у модалок (16–24px) и пилюль (кнопки — 20px),
  тени `--shadow-modal`/`--shadow-card`, шрифт `--font-sans` (Inter).
- Модалка живёт в `.strum-modal-overlay` + `.strum-modal-content` (те же
  классы, что у остальных диалогов — единый вид оверлея/карточки).

Хардкод цветов ЗАПРЕЩЁН (текущая беда: «Стереть» = `#486d48`, баррэ
местами инлайн). Всё — через переменные.

Анимации: НЕ добавлять новых (в редакторе сейчас всего одна анимация —
подсказка «По аппликатуре»; обрамление действий анимациями — отдельная
волна B-08). Допустимы дешёвые `:hover`/`:focus` смены фона/границы через
`transition` фона/границы 0.15s — как у уже существующих кнопок.

## 2. Что должно остаться (полный функционал — критично)

### Интерактивный гриф `createInteractiveFretboard(initialShape, onChange, opts)`
Возвращает объект с методами (сигнатура НЕ меняется — от неё зависит
редактор и тесты):
- `container` — корневой DOM-узел;
- `setIntervals(intervals)` — показать/убрать подписи интервалов в точках;
- `clear()` — сбросить в `[x,x,x,x,x,x]`, снять баррэ-офф, вызвать onChange;
- `getShape()` — текущая форма (массив 6: число лада, `0` или `'x'`);
- `getBarreOff()` — отсортированный массив ладов с «разжатым» баррэ.

Взаимодействия (все сохранить):
1. **Клик по ячейке лада** ставит/снимает палец (повторный клик по той же
   → `'x'`).
2. **Клик над порожком** по струне циклит открытая(`0`) ↔ приглушить(`'x'`).
3. **Окно ладов**: авто-выбор `gridStartFret` тем же алгоритмом, что в
   `renderFingeringSVG` (превью и редактор ОБЯЗАНЫ показывать одно и то
   же). Кнопки сдвига вверх/вниз (двигают всю форму на ±1 лад, с
   защитой границ 0..16) — показывать, только когда сдвиг осмыслен, как
   сейчас. Номер лада подписывать слева, когда окно не от порожка.
4. **Баррэ**: рисовать капсулой по выбору модели хвата `analyzeShapeGrip`
   (тот же выбор, что в превью). Кнопка-тумблер «разжать баррэ» (B-74) у
   баррэ: помечает лад в `barreOff` → капсула распадается на отдельные
   точки; повторное нажатие собирает. Форму пальцев это не меняет.
   Состояние читается из `opts.barreOff`, отдаётся через `getBarreOff()`.
5. **Интервалы**: если анализ формы дал интервалы, внутри точек
   показывать их (как сейчас), по `setIntervals`.
6. Крестик приглушения — цвет `--color-danger`; открытая струна —
   кружок-контур `--fingering-open-marker`; точки пальцев —
   `--color-ink`; баррэ — `--color-ink`.

### Модалка `openFingeringEditor(chordName, variantIndex, wrapper, opts)`
- Два режима: `opts.createMode` («Новый аккорд по аппликатуре», пустой
  гриф, кнопка «Добавить аккорд», имя определяется по форме) и правка
  существующей ячейки (заголовок «Редактор аппликатуры: <аккорд>»,
  кнопка «Сохранить»).
- **Строка анализа**: показывает распознанное по грифу имя аккорда;
  рядом кнопка «Переименовать?» — появляется только когда распознанное
  имя ≠ текущему имени ячейки; переименовывает ячейку на лету (модель +
  инпут + подсветка ступеней) без закрытия редактора.
- **Кнопки**: «Отмена», «Стереть», «Сохранить»/«Добавить аккорд». В
  режиме правки — плюс «Сохранить для всех <аккорд>» (B-76): применяет
  форму (лады + баррэ) ко всем вхождениям аккорда; при наличии вручную
  закреплённых ячеек — окно подтверждения, иначе молча.
- **Снимок/откат**: при входе снимается `entrySnapshot`; «Переименовать?»
  меняет модель сразу, но выход без сохранения (Отмена/клик по
  оверлею/Esc — через `trapFocus`) обязан вернуть имя/форму/баррэ как
  было.
- **Сохранение** (обе кнопки) сохраняет логику 1-в-1: `pinCurrentFinger‐
  ingsForChord` → `upsertUserFingering` (пара {лады,баррэ}) →
  `userFingerings.set` → `fingeringCache.clear()` → `setPreferredFinger‐
  ing(...barreOff)` → `updateCellsDegrees()`; в createMode — ветка с
  `setEventChord`/`refreshAutoDetectedKey`/`previewChordNow`; при
  «для всех» — `applyFingeringToAllOccurrences` + `countPinnedOccurrences`
  для окна.
- Совместимость: те же id/классы, на которые опираются тесты и вызовы —
  `#save-fingering`, `#clear-fingering`, `#cancel-fingering`,
  `#apply-detected-chord`, `#chord-analysis`,
  `#fingering-editor-heading-chord`, контейнер грифа; классы модалки
  `.strum-modal-overlay`/`.strum-modal-content`.
- Вызовы-потребители не трогаем: `openFingeringEditor` (строки ~15539,
  ~24138), `openFingeringEditorForNewChord` (~17819, зовётся ~28693).

## 3. Целевой вид (как должно выглядеть)

Ощущение: компактная светлая карточка «как остальные диалоги», гриф —
чистый и «дышащий», без грубых бордюров-квадратиков у кнопок сдвига,
без пёстрых цветов. Иерархия действий читается с одного взгляда.

Компоновка сверху вниз:
1. **Заголовок** — имя аккорда как акцент, размер как у других модалок.
2. **Гриф** по центру: крупнее и легче нынешнего; тонкие струны/лады,
   аккуратный порожек, номер лада — приглушённый. Маркеры над порожком
   (◯/✕) выровнены по струнам, не «прилеплены».
3. **Строка состояния**: чип с распознанным аккордом (мягкий фон
   `--color-neutral-bg`, текст `--color-text-primary`); «Переименовать?» —
   лёгкая контурная кнопка рядом.
4. **Кнопки действий** одной ровной строкой, единый стиль пилюль:
   - «Отмена» — нейтральная (тихая);
   - «Стереть» — вторичная/приглушённая (НЕ зелёная; через переменные;
     тон danger-lite или нейтраль с danger-текстом);
   - «Сохранить»/«Добавить аккорд» — залитая `--color-ink` (главное);
   - «Сохранить для всех» (правка) — вторичный акцент, визуально ЛЕГЧЕ
     главной, но заметно отличается (например, контурная в
     `--color-accent`): не массивная, не конкурирует с «Сохранить».
     Показ по наведению на «Сохранить» (как договорились в B-76) —
     мгновенный, без анимации масштаба.

Сдвиг ладов: минималистичные шевроны (‹/›/▲/▼) без рамок-коробок, в цвет
`--color-text-tertiary`, увеличиваются по hover фоном-подсветкой, а не
бордюром.

Управляемость: цель клика по ладам/струнам ≥ комфортной (не мельчить),
но сам гриф не «раздутый». Всё центрируется, поля скромные.
