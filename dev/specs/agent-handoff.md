# Заметки для следующего агента: ошибки и тупики

Файл для того, кто продолжит работу после 0.704. Здесь собрано только то, что
уже стоило времени: где легко наступить на те же грабли. Проверять по дате —
если запись устарела, правьте её, а не обходите.

Обновлено: 2026-10-28, версия 0.704.

## 1. Среда песочницы

- После отката песочницы пропадают git-история, `node_modules` и `/tmp`.
  Порядок восстановления: `git fetch` (с `-c http.version=HTTP/1.1`, иначе
  бывает обрыв) → `git merge --ff-only origin/arena/…` → `npm install` →
  распаковать `al2023.tar.br` в `/tmp/al2023` → поднять сервер на 8000.
- Puppeteer требует трёх переменных, иначе Chromium не стартует:
  `PUPPETEER_EXECUTABLE_PATH=/tmp/chromium`, `LD_LIBRARY_PATH=/tmp/al2023/lib`,
  `NODE_PATH=node_modules`.
- Тесты, которым нужен настоящий браузер и `http://`, читают `STRUCHORD_URL`.
  Для второго worktree (`/tmp/main-check`, там `origin/main` 0.679) — порт 8001,
  иначе тест молча проверяет не ту сборку.
- Полный корпус `bash dev/run-tests.sh` идёт около 30 минут и занимает порт 8000.
  Запускать только фоновым процессом, а не через обычный вызов с таймаутом.

## 2. Тесты: где легко ошибиться

- **Проверка может держаться за то, что уже удалено.** `b12-tab-techniques-browser.js`
  искал атрибут `data-tab-tech-mark`, а он исчез ещё в 0.692 вместе с самодельной
  отрисовкой мини-таба (его рисует alphaTab). На `origin/main` набор был зелёный,
  потому что там старая сборка. Вывод: сначала `git log -S"<имя атрибута>"`,
  потом решать — тест устарел или поведение потеряно. Молча вычёркивать проверку нельзя.
- **alphaTab рисует кадр не мгновенно.** После «Применить» проверять картинку сразу
  бессмысленно: нужно ждать `[data-tab-thumb][data-thumb-done] svg`.
- **Служебный `<svg>` для `<defs>` не должен иметь числовых `width`/`height`.**
  Аудит B-79 считает `width="0" height="0"` немасштабируемым размером
  (`svg-size = 1` при допустимом 0). Размеры держим в CSS (`width:0;height:0`),
  числовые атрибуты не возвращаем. На 0.679 аудит проходил — регресс появился позже.
- **Шапка главного экрана на 320 px** — давнее падение `b13-home-screen.js`
  (шапка занимала 367 px). Лечится `flex-wrap: wrap; row-gap` у `.home-header`
  и `margin-left: auto` у `.home-header-controls`. Не убирать — вернутся 3 FAIL.
- **Мобильная главная и инлайн-элементы.** Любая вставка в строку названия ломает
  390 px: появлялась горизонтальная прокрутка 54 px. Нужна обёртка-колонка
  (`.home-brand-text`), а не инлайн-текст рядом с логотипом.
- **Цвет и контраст.** `--color-text-tertiary` не проходит WCAG AA (3,22:1).
  Мелкие подписи — `--color-text-secondary` (8,68:1). Проверять замером, не на глаз.

## 3. Реестр версий

- Хеш и размер в реестре `ROADMAP.md` устаревают дважды: после смены цвета и после
  правки svg. Пересчитывать `sha256sum` + `stat -c %s` **в самом конце**, после
  последней правки `STRUCHORD.html`.
- `check-versions.js` правит шапки README и ROADMAP только с `--fix`; `sw.js`
  он не трогает — `CACHE_NAME` менять руками вместе с версией (R7).
- Перед заменой строки проверять, что вхождение одно (`s.count(old) == 1`),
  иначе можно испортить соседнюю запись реестра.

## 4. Правки HTML

- Правило владельца: «HTML руками не правь — все правки делает патч». Правка 0.704
  была внесена напрямую (`edit_file`/`python3`), патч-скрипта для неё нет. Если
  появится такой же случай — либо делать патч в `dev/tools/`, либо честно сказать.
- Не перезаписывать `STRUCHORD.html` своей копией. При «ПАТЧ НЕ ПРИМЕНЁН» просить
  у владельца полный текст ошибки.
- Синтаксис проверять только `node dev/tools/check-html-syntax.js` (9 скриптов,
  6 вставок), а не сторонними парсерами.

## 5. Документы и снимки

- Снимок экрана хранится, только если на него ссылается отчёт (R13).
  `python3 dev/tools/prune-screenshots.py` показывает лишние; `--apply` удаляет.
- В `prune-screenshots.py` была ошибка: строка вида «1/3» (счётчик кадров в
  `REPORT.md`) совпадала с шаблоном диапазона, и скрипт считал папку проверенной,
  не прочитав её содержимое. Проверено на 0.703 — после починки нашлось 18 папок,
  которые раньше молча пропускались.
- `dev/bench/123` (4 байта, ни к чему не относится) — пример мусора, который
  появляется от случайных команд. Такой файл удаляется сразу.

## 6. Git и PR

- Пуш только в ветку текущей сессии `arena/…`, без force-push (R9).
- Перед PR: `git fetch` → `git rev-list --count origin/main..HEAD` → `git merge-tree
  --write-tree` на конфликты. Мусор вроде `*.bak`, `*.log`, архивов из `uploads/`
  в ветке не должен попадать в PR.
- Перегенерированные кадры тестов после прогона корпуса показываются как изменённые
  PNG. Это не правка продукта: смотреть на них глазами не нужно, перед коммитом
  такие файлы откатывать (`git checkout -- dev/bench/results`), а не тащить в историю.
