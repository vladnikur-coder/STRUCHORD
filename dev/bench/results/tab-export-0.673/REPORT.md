### Шесть струн: что реально читает сторонний движок

| STRUCHORD `string` | Физическая струна | Струна в binary GP5 | GPIF String | alphaTab model string | MIDI стандарт / Drop D |
| --- | --- | --- | --- | --- | --- |
| 0 | 6-я, низкая | 6 | 0 | 1 | 40 / **38** |
| 1 | 5-я | 5 | 1 | 2 | 45 / 45 |
| 2 | 4-я | 4 | 2 | 3 | 50 / 50 |
| 3 | 3-я | 3 | 3 | 4 | 55 / 55 |
| 4 | 2-я | 2 | 4 | 5 | 59 / 59 |
| 5 | 1-я, высокая | 1 | 5 | 6 | 64 / 64 |

Важно: alphaTab считает собственные `Note.string` снизу с 1. Это не номер физической струны гитары и не нумерация binary GP5. Внешний дамп нельзя ошибочно читать как «перевёрнутые струны».

## Что именно независимо проверено

- **GP5:** vendor alphaTab 1.8.4 вырезается по маркеру бандла, а не по номеру строки, и запускается в отдельном Node VM без функций STRUCHORD. Передаются исходные экспортные bytes. Для кириллицы задан `windows-1251`. Два файла дополнительно прочитаны PyGuitarPro 0.11.
- **GPX:** BCFS/BCFZ и круг через собственный импорт проверяют существующие GPX-тесты. Для независимой проверки нот и структуры извлекается **неизменённый `score.gpif`**, который тестовый помощник кладёт в минимальный GP7 ZIP: этот XML читает GP7-reader alphaTab. Тест **не выдаётся за независимое чтение BCFS/BCFZ**. Контрольный исходный XML сохранён рядом с каждым GPX.
- **MIDI:** используется сторонний `midi-file` 1.2.4, не MIDI-reader приложения. В Chromium после клика перехватывается исходный Blob, не заменяется download-функция и не строится подставной файл.
- **Внешние приложения:** Guitar Pro и DAW здесь не запускались. Для внешней приёмки нужно открыть приложенные файлы у владельца и проверить расположение/время/звучание. Отсутствие такого запуска не скрывается за зелёным собственным roundtrip.

## Что не закрывается этой сдачей

- **m1–m5** исходного отчёта не реализованы: подписи пауз/счётчик, стартовая струна, ширина ленты, GP-импорт с сохранением табовой позиции.
- Новые drag/межсекционные операции, подпись вставки и согласованное транспонирование с предупреждениями — не предмет E4 и не объявляются выполненными.
- Полная первая подсказка, все бюджеты ввода/открытия, подсветка отдельных нот, весь Going to the Run и финальная матрица приёмки остаются отдельным следующим этапом.
- GP/MIDI-import не превращает импортированные ноты во вставки; сохранён dev-фундамент «Партий».
- MIDI — ноты, не запись гитарного синтеза. Гитарные приёмы, EQ/реверберация, оформление, мастер-громкость/панорама и автоматизация тембра партий имеют явно описанные потери. 15 мелодических каналов + канал 10 ударных; при превышении экспорт отклоняется.
- Нативный swing аккомпанемента не переносится этим этапом: MIDI содержит письменный ритм; GP5 больше не навязывает swing всем восьмым.

Из корня репозитория:

```bash
bash dev/tools/setup-acceptance.sh
# В другом терминале, оставить работающим:
python3 -m http.server 8000 --bind 0.0.0.0

node dev/tools/check-html-syntax.js
B12_E4_RESULTS=dev/bench/results/tab-export-0.673 node dev/tests/b12-tab-export.js
B12_E4_RESULTS=dev/bench/results/tab-export-0.673 node dev/tests/b12-midi-export-browser.js

/tmp/gpvenv/bin/python dev/tools/gp5-py-oracle.py \
  dev/bench/results/tab-export-0.673/six-strings-e-std.gp5 --json
```

Без `B12_E4_RESULTS` новые тесты не создают артефактов в репозитории. Браузерный тест требует сервер на 8000 (или `STRUCHORD_URL`), как остальные живые тесты проекта. Внешние npm-зависимости нужны только проверкам, не приложению.
