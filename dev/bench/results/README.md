# Снимки и результаты проверок

Здесь лежат папки волн: `dev/bench/results/<волна>/`.

## Что в папке

| Файл | Что это | Хранится всегда |
|---|---|---|
| `checks.json` | числа и исходы проверок этой волны | да |
| `REPORT.md` | отчёт: что проверяли, что получилось, кадры | если писался |
| `*.png` | снимки экрана | только те, на которые ссылается отчёт (правило R13) |
| `*.log` | сводки прогонов, на которые ссылается отчёт | да |

## Правило снимков (R13)

Снимок остаётся в ветке, только если он назван в отчёте — в `REPORT.md` своей папки,
в `README.md`, `ROADMAP.md` или в `dev/specs/`. Остальные кадры съёмки удаляются:
это промежуточные варианты (светлая/тёмная/телефон), которые никто не открывает.

Проверить и почистить:

```bash
python3 dev/tools/prune-screenshots.py          # только показать
python3 dev/tools/prune-screenshots.py --apply  # удалить
```

## Удалённый кадр можно вернуть

История Git не переписывается, поэтому любой снимок достаётся из прошлого коммита:

```bash
git log --oneline -- dev/bench/results/<волна>     # найти коммит
git checkout <коммит> -- dev/bench/results/<волна> # вернуть папку целиком
```

Так же возвращается старый `dev/tmp/STRUCHORD.w3.bak` (полная копия приложения версии 0.57),
если когда-нибудь понадобится сверка с той волной.

## Почему у части волн нет снимков

У волн `tab-gp8-0.681 … 0.696`, `tab-drag-0.699` и `logo-0.698` отчёта с картинками не писалось:
их результаты записаны числами в `checks.json`, а решения — в
`dev/specs/tab-insert/approved-decisions.md` и `ROADMAP.md`. Снимки этих волн удалены как
невостребованные; при необходимости они возвращаются командой выше.
