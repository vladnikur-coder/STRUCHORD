## 3. Модель данных

### 3.1 Дорожки

```js
song.tracks = [
  {
    id: 1,
    instrument: 'guitar',          // 'guitar' | 'keys' | будущие
    name: 'Гитара',
    volume: 100, mute: false, solo: false,
    chords:  { '12:34:0': 'Am' },          // разреженная карта, только свои аккорды
    voicings: { '12:34:0': 2 },            // выбранный вариант позиции
    keyboardSize: null,                    // null = как в песне; иначе 25/37/49/61/76/88
    patterns: { '12:34:0': {...} }         // рисунок аккомпанимента на ячейку
  },
  { id: 2, instrument: 'keys', ... }
];
song.activeTrackId = 1;
song.keyboardSize = 61;      // умолчание песни; дорожка может переопределить
// главная = song.tracks[0]
```

**Ключ ячейки** — `` `${secId}:${squareId}:${eventIndex}` ``. Он структурный, не зависит от аккорда, не зависит от номера прохода повтора (повторы разворачиваются только при показе ленты, как сейчас в `renderTimeline`).

**Разреженные карты.** Храним только то, что реально задано. Пустое значение = «аккорда у этой дорожки нет». Для песни на 1000 ячеек и 3 дорожек это десятки килобайт, что безопасно при лимите localStorage ~5 МБ.

### 3.2 Зеркала для старого кода (ключевое решение)

В коде 0.691 больше сотни мест читают `ev.chord` и `ev.strumPattern` напрямую. Переписывать их — огромный риск. Поэтому:

- **Источник истины** — карты дорожек (`track.chords`, `track.patterns`).
- **Зеркала** — `ev.chord`, `ev.strumPattern`, `ev.fingering` остаются в старой модели и всегда равны значениям **главной дорожки**.
- Функция `syncMirrors()` вызывается после любой правки через `songStore.dispatch`: она перекладывает значения главной дорожки в `ev.*`.
- Старые тесты, круг аккордов, анализ гармонии, лента, GP-экспорт продолжают работать с `ev.chord` и ничего не подозревают.
- Активная дорожка читается новыми панелями через `chordForTrack(ev, trackId)`; если там пусто — призрачная подсказка из главной.

**Важно:** перетаскивание дорожек меняет, кто главный. После него `syncMirrors()` обязан переписать `ev.chord` под новую главную — иначе картинка и экспорт поедут. Это одна команда `dispatch('track/reorder')`, один шаг Undo.

### 3.3 Призрачный аккорд

В ячейке активной неглавой дорожки, где своего аккорда нет:

- показывается **полупрозрачный** аккорд главной дорожки (например, бледный `Am`);
- дорожка в этом такте **молчит** — звука нет;
- бледный аккорд **не анализируется** гармонией, не попадает в экспорт нот; **ступени, ладовая заливка и подписи гармонии в такой ячейке гаснут** (решение 33);
- клик по такой ячейке открывает круг аккордов и записывает аккорд **в активную дорожку**, после чего он становится полноцветным и начинает звучать.

### 3.4 Перетаскивание

Механику берём из Songmap (секции, B-64/B-68): ручка захвата, FLIP-анимация, гистерезис, **коммит на `pointerup`**, на `pointermove` — только `transform`, без полного `render()` и без reflow (правило 60 fps из README). Первая после перетаскивания строка становится главной.

### 3.5 Миграция

`sanitizeSongData` (75092) при загрузке файла без `song.tracks`:

1. создаёт одну дорожку `{ id: 1, instrument: 'guitar', name: 'Гитара', volume: 100 }`;
2. для каждого события с `ev.chord` пишет `track.chords[cellKey] = ev.chord`;
3. переносит `ev.strumPattern` / `sec.strumPattern` в `track.patterns`;
4. `activeTrackId = 1`.

Открыть-сохранить старую песню без правок должно дать **тот же JSON** (как в 0.659 проверяли для нот). Это отдельный тест.

## 4. Экраны и взаимодействия

### 4.1 Панель воспроизведения

```
[▶] [⏸] [■] [ BPM 120 ] [🎛 Микшер · Клавиши] [🎸 гриф] [?]
```

Кнопка микшера — `ti-adjustments` (есть в урезанном шрифте). Подпись включает имя **активной** дорожки, чтобы было видно, что редактируешь, даже когда панель закрыта. Отдельного переключателя в шапке нет.

### 4.2 Микшер

```
┌─ Микшер ──────────────────────────────────────────────┐
│ ≡  ● Гитара      ▁▃▅▇▇ 100  [M] [S]  ⋯                 │
│ ≡    Клавиши     ▁▃▅▇▇ 100  [M] [S]  ⋯                 │
│                                                        │
│ + Добавить дорожку                                      │
└────────────────────────────────────────────────────────┘
```

`●` — активная, `≡` — ручка перетаскивания. M/S работают как в обычном микшере: соло глушит остальные, мьют глушит себя. Ни панорамы, ни EQ, ни Мастера.

### 4.3 «+» и «⋯»

- **«+» при наличии дорожек** — копия активной: те же аккорды, новый инструмент (выбирается сразу), громкость 100.
- **«+» при пустой песне** — создаёт первую (главную) дорожку и **сразу спрашивает инструмент**: «Гитара» / «Клавиши» (решение 31). Без этого сетка останется беззвучной и непонятной. Молчаливую гитару по умолчанию не создаём.
- **«⋯»** — маленькое меню, один пункт: «Инструмент». Список: Гитара, Клавиши (+ заглушки «скоро» для будущих). Смена инструмента меняет звук, аппликатуру, набор аккомпаниментов и иконку строки. Аккорды при этом **сохраняются**.

### 4.4 Пустая песня

Сетка секций видна, но ячейки без надписей. Поверх — мягкая плашка «Добавьте дорожку, чтобы песня зазвучала» и та же кнопка «+». Не белый экран, не ошибка.

### 4.5 Ячейка

```
┌──────────────┬──────────────┐
│ Am           │ Am  (бледный)│ ← активная = Клавиши, своего аккорда нет
│              │              │   звука нет
└──────────────┴──────────────┘
```

Слева — главная дорожка (если она активна), справа — призрачная подсказка. Бледный текст не кликабелен как текст: клик по ячейке открывает круг.

### 4.6 Аппликатура клавиш (вместо грифа)

```
┌─ Клавиши · Am ──────────────────┐
│  ┌─┬─┬─┐ ┌─┬─┬─┬─┐             │
│  │ │█│ │ │█│ │█│ │ │  █ = нота  │
│  │ │█│ │ │█│ │█│ │ │  ● = корень│
│  │ └┬┘ │ │└┬┘└┬┘ │ │           │
│  └──┴──┘ └──┴──┴──┘ │           │
│  A   C   E           │
│  ●   2   4      ← пальцы (можно выключить)
│  Левая: бас A₂       │
│  ‹ 2/5 ›             ← листание вариантов
└──────────────────────────────────┘
```

Показывается в трёх местах: подсказка над аккордом (31032), закреплённая карточка (31603/31645), панель «Сейчас» в ленте (57391). Везде — для активной дорожки.

**Закреплённая панель клавиатуры (решение 35).** Под панелью воспроизведения висит отдельная панель — там же, где сейчас закрепляется карточка аппликатуры гитары (механика B-67, `syncPinnedFingeringWithPlayback` на 31759). Это **одна и та же панель**: активна гитара — рисуем гриф, активны клавиши — рисуем клавиатуру выбранного размера целиком, с подсвеченными нотами текущего аккорда. Второй независимой панели не заводим. Если ты имел в виду именно две разные панели — это единственное место, которое надо поправить до кода (раздел 14).

Размеры: viewBox в px, внешние размеры в `rem`, уважаем `--ui-scale`; проверяем на 390 / 1024 / 1280 px и в светлой/тёмной темах. На 88 клавиш на узком экране — горизонтальная прокрутка или авто-масштаб, без нативного `zoom`.

### 4.7 Панель «Аккомпанемент»

Открывается кнопкой в ячейке/секции (там же, где сейчас «Бой/перебор»). На гитарной дорожке кнопка и содержимое остаются прежними; на клавишной — новые:

```
┌─ Аккомпанемент ────────────────────────────────┐
│ Тип:  [Целый аккорд] [Арпеджио ↑]              │
│       [Бас+аккорд]   [Вальс]                   │
│       [Альберти]     [Октавный бас]            │
│ Клавиатура: ☑ как в песне (61)                 │
│             ☐ своя: [25][37][49][61][76][88]   │
│ Рисунок на такт:  ♩ ♩ ♩ ♩  (свинг ☐)           │
│ Применить к: [ячейке] [секции]                 │
└────────────────────────────────────────────────┘

Вместо «диапазона нот» теперь **размер клавиатуры** (решения 34, 36): умолчание на песню, дорожка может переопределить. Диапазон MIDI-нот выводится из размера по таблице раздела 6. При смене размера все варианты позиций и закреплённая панель пересчитываются. Пресеты ведут себя как бои: наследуются секцией, тянутся при ресайзе ячейки, уважают свинг, подсвечивают шаги при игре. Чипов с нотами в ячейке нет.

### 4.8 Лента

Без изменений, кроме аппликатуры в панели «Сейчас»: она теперь рендерится по инструменту активной дорожки. Падающие полоски — **отдельная будущая идея**, в этом патче не проектируются (см. раздел 13).

## 5. Как реализовывать по этапам

Один `.patch`, но шесть логических этапов. Каждый принимается отдельно; порядок жёсткий.

### Этап 0 — B-102, отдельная волна до режима (R5)

**Цель:** `getChordNotes` перестаёт быть одновременно формулой, звуком и аппликатурой.

- Ввести `chordFormula(name, key)` — канонический список **классов высоты** с интервалами для любого аккорда: трезвучия, септаккорды, `sus2/sus4`, `add9`, `9/11/13`, `dim/aug`, `5`, `alt`, слэш-бас.
- Никаких пропусков нот. В частности `C11` и `C13` содержат все свои тона; энгармоника (`Cb`, `B#`, `E#`, `Fb`) уже исправлена в B-101 — сохраняем.
- `getChordNotes` остаётся публичной обёрткой для существующего кода, но внутри зовёт `chordFormula`. Поведение гитары **дословно прежнее** — тесты `b101`, `b262`, золотая таблица аппликатур обязаны пройти без изменений ожиданий.
- Заделы под инверсии/удвоения в этой волне **не делаем** (объём «только честный список нот»).
- Приёмка: таблица из ~80 аккордов, сверка нот в 12 тональностях, регрессия всего корпуса.

**Почему первым:** иначе пианино унаследует гитарные пропуски (`C11` без терции и т.п.), что прямо запрещено R12.

### Этап 1 — модель, Store, миграция

- Новые поля в `song`: `tracks`, `activeTrackId`.
- `cellKey(sec, sq, ei)`, `trackChord(trackId, ev)`, `setTrackChord(...)`, `syncMirrors()`.
- Все мутации — `songStore.dispatch('track/…')`, история и рендер достаются бесплатно.
- `sanitizeSongData` (75092): allowlist инструментов, миграция старых файлов, отбрасывание битых значений (не «зажатие» — правило из README); лимиты на число дорожек и длину карт.
- Сохранение в `.struchord`: новые поля пишутся, старые файлы читаются, round-trip стабилен.
- Приёмка: 8 старых песен открыть-сохранить → тот же состав; новая песня → пустой `tracks`.

### Этап 2 — микшер

- Кнопка в транспорте (иконка `ti-adjustments`), панель как в 4.2.
- Строки: громкость (0–100), M, S, «⋯», ручка drag, клик → активная.
- Перетаскивание по образцу Songmap: commit на `pointerup`, FLIP, гистерезис, один Undo; после перестановки — `syncMirrors()`.
- «+» и «⋯» по 4.3; новая/пустая песня по 4.4.
- `activeTrackId` сохраняется в песне.
- Приёмка: соло/мьют реально влияют на звук, перетаскивание меняет главную и призрачные аккорды, Ctrl+Z возвращает порядок.

### Этап 3 — звук (два шага)

**Шаг 1 (быстро).** Подключаем уже существующий простой клавишный тон: `partSchedulePitchNote` (64694) даёт `triangle`-осциллятор, `partPitchFrequency` (60189) — высоту. Но **не** через Партии: выносим воспроизведение одной ноты в независимую функцию `playKeysNote(ctx, midi, startTime, duration, gain, channel)`, которую использует и режим клавиш.

**Шаг 2 (замена).** Вместо `triangle` — собственный синтез пианино без сэмплов:
- 5–7 парциалов с лёгкой негармоничностью (`f_n = n·f_0·√(1+B·n²)`),
- короткий шумовой «молоток» на атаке (2–6 мс),
- экспоненциальное затухание, своё для каждого парциала,
- опциональная педаль (общий хвост), без UI в этой волне,
- один `GainNode` на дорожку → существующая шина `ensureMixerChannel` (43494) → мастер.

Обязательно: `resumeAudioContext()` для Safari-`interrupted`, `activeOscillators` для уборки, ограничение одновременно звучащих голосов, никаких сетевых запросов.

- `soundChannelInstrument` (43352) сейчас жёстко возвращает `'guitar'` для канала «Песня» — заменить на инструмент активной/конкретной дорожки.
- `PART_SOUNDS.keys` (43149) расширить пресетами (рояль / электропиано / орган) — но **без** выбора в «⋯»: выбираем один дефолтный, остальные на будущее.
- Приёмка: обе дорожки звучат одновременно, громкость/M/S слышны, нет щелчков и «залипших» нот, Safari/iPad не теряет звук после сворачивания.

### Этап 4 — аппликатуры, варианты, голосоведение

- `renderKeysVoicingSVG(voicing, opts)` — рядом с `renderFingeringSVG` (29984). Единая точка `renderVoicingForActiveTrack()` выбирает рендер; четыре места вызова (31032, 31603, 31645, 57391) переключаются на неё.
- `generateKeysVoicings(formula, keyboardSize, prevVoicing)` — диапазон берётся из таблицы размеров (раздел 6), а не из двух выпадающих списков:
  1. бас — корень или нота слэш-баса, отдельной низкой нотой;
  2. правая рука — тона аккорда в заданном диапазоне, удвоение корня;
  3. выбрать вариант с минимальным суммарным движением относительно предыдущего аккорда;
  4. если тонов больше, чем может взять рука — приоритет: корень → терция → септима → расширения; квинта и одиннадцатая уходят первыми.
- **Правило 4 — документируемая инструментная конвенция (R12).** Это не «пропуск нот» в формуле, а ограничение руки. Зафиксировать в README отдельным абзацем: «гитара может не играть часть тонов из-за аппликатуры; фортепиано обязано играть каноническую формулу, а при нехватке пальцев отбрасывает только квинту/ундециму по такому-то правилу». Гитарный путь это правило не применяет.
- Варианты: счётчик «2/5» и кнопки «‹ ›» как у гитары; выбранный индекс — `track.voicings[cellKey]`, одна команда Undo. Ручного перетаскивания нот нет.
- Пальцы: подсказка 1–5, управляется существующей галочкой `showFingers`. Солвер не нужен: пальцы — рекомендация, не проверка (R12: лучше не показывать, чем показать неверно).
- Закреплённая панель клавиатуры: `renderPinnedKeyboard(size, voicing)` рисует **все** клавиши выбранного размера (например 61) и подсвечивает ноты текущего аккорда; переиспользует механизм пина B-67, не создаёт второй панели. На узких экранах — прокрутка.
- Приёмка: Am→F→C→G рука не прыгает; `C/E` даёт отдельный бас E; 13-й аккорд не теряет терцию и септиму; смена размера 49→88 меняет диапазон и картинку; на 390 px панель прокручивается.

### Этап 5 — типы аккомпанимента

- Шесть пресетов рядом с `STRUM_PRESETS` (46229), `mode: 'keys'`:

| id | Название | Идея шагов (на 4/4) |
|---|---|---|
| `keys-block` | Целый аккорд | аккорд на каждую долю |
| `keys-arp-up` | Арпеджио ↑ | тона аккорда снизу вверх по восьмым |
| `keys-bass-chord` | Бас + аккорд | бас на 1 и 3, аккорд на 2 и 4 |
| `keys-waltz` | Вальс | бас — аккорд — аккорд (3/4) |
| `keys-alberti` | Альберти-бас | корень — квинта — терция — квинта |
| `keys-octave-bass` | Октавный бас | корень через октаву + аккорд |

- **Токены шагов** (не ноты, а роли — чтобы работала транспозиция): `H` = весь аккорд, `B` = бас, `O` = корень через октаву, `t1/t3/t5/t7/t9/t11/t13` = тон аккорда по интервалу, `null` = тишина.
- `cloneSafePattern` (74999) и санитайзер пула (~39027) учатся режиму `keys` и новым токенам; `subdivision` остаётся 1/2/3/4; свинг — общий.
- `validateStrumPresets` (46431) получает ожидаемое число ударов для шести новых пресетов; `isPresetCompatible` (46522) не меняется — геометрия сетки одна.
- `schedulePatternForEvent` (45823) получает третью ветку `keys`: токен → реальные MIDI-ноты через `generateKeysVoicings` → `playKeysNote`. **Запрещено** вызывать в этой ветке `resolveFingeringShape`, `shapeToPluckNotes`, `getBassStringsForShape` — они несут гитарные пропуски (R12).
- `getEffectiveStrumPattern` (44908) и `getSlicedPatternForEvent` (44921) обобщаются на «паттерн дорожки»: приоритет свой ячейки → секции, как сейчас.
- `scheduleStrumStepHighlight` (45804) подсвечивает шаги и для клавиш.
- Кнопка «Аккомпанемент» в ячейке/секции открывает панель 4.7; размер сохраняется в `track.keyboardSize` (`null` = как в песне), умолчание песни — `song.keyboardSize`.
- Приёмка: все шесть пресетов звучат в 4/4, 3/4, 6/8; свинг не ломает сетку; ресайз ячейки не обрывает рисунок; подсветка шагов совпадает со звуком.

### Этап 6 — экспорт, версия, реестр

- `.struchord` — полная модель дорожек.
- MIDI SMF format 1 — по дорожке на инструмент; клавишная получает GM program 0 (`Фортепиано`), `midiInstrumentFor` (77364) уже умеет определять `keys`.
- GP5/GPX — по дорожке, **настоящий нотный стан с абсолютными высотами** (решение 37), не таб и не «только символы аккордов». Писатели `gp35*` (~78151+) заточены под шесть струн, поэтому добавляется отдельная ветка «стан без табулатуры»: ноты берутся из pitch-домена (`partScoreNotePitch` 62227, `partScoreNotesInBar` 62240, `partScoreClefForNote` 62967 — это **конвертеры данных** из архивного B-12.11, UI Партий не включается), ключ — скрипичный/басовый по регистру, символ аккорда ставится над долей. Проверка — независимым alphaTab и MIDI-ридером, как в 0.673. Это самый рискованный кусок волны.
- R7: поднять `STRUCHORD · ver 0.692` (15203) и `CACHE_NAME` в `sw.js`; выкладывать парой.
- R6: строка в реестр релизов `ROADMAP.md` с версией, sha256, размером, версией кэша.
- R9: коммит только в ветку текущей Arena-сессии.

## 6. Музыкальная корректность (R12)

Правила, которые программист обязан соблюдать:

1. **Написание аккордов общее.** `Cb`/`B`, `E#`/`F`, `B#`/`C`, `Fb`/`E`, джазовые `CM7`, `C-7`, `Δ`, диезы/бемоли по тональности — всё через существующие `normalizeChordCase`, `correctDisplayedChordName`, `readableChordNames`. Никаких «пианинных» вариантов написания.
2. **Анализ гармонии общий.** Ступени, ладовые профили, V/x, заливки ячеек считаются одним движком для всех дорожек. Для ячейки берётся аккорд активной дорожки; призрачный аккорд не анализируется.
3. **Гитарные упрощения не переезжают в фортепиано.** `getChordNotes`, `strumChord`, `shapeToPluckNotes`, `accompCellNotes` учитывают аппликатуру и могут терять тона. Клавишный путь строится от `chordFormula` (этап 0).
4. **Отбрасывание тонов рукой — документируется.** Приоритет из этапа 4 занести в README как инструментную конвенцию с обоснованием.
5. **Слэш-бас.** `C/E` — бас E отдельной низкой нотой, а не перестановка аккорда вверх. Проверить в звуке, в аппликатуре, в MIDI-экспорте и в подписи.
6. **Размер клавиатуры вместо диапазона.** Диапазон MIDI-нот выводится из выбранного числа клавиш. Честная таблица (первая нота → последняя, включительно):

| Клавиш | Первая | Последняя | MIDI |
|---|---|---|---|
| 25 | C3 | C5 | 48–72 |
| 37 | C2 | C5 | 36–72 |
| 49 | C2 | C6 | 36–84 |
| 61 | C2 | C7 | 36–96 |
| 76 | E1 | G7 | 28–103 |
| 88 | A0 | C8 | 21–108 |

Умолчание песни — **61** (самое частое MIDI-фортепиано); дорожка может переопределить. Левая рука/бас берёт нижнюю октаву выбранного диапазона, правая — середину; при 25 клавишах обе руки делят один маленький диапазон, и об этом надо честно написать в подсказке панели. Умолчание 61 — предположение, поправь, если хочешь 88.
7. **Никаких «усреднённых» аккордов.** Если аккорд не распознан — честная пустота и подсказка, а не подстановка похожего (как с бараньей высотой в B-101).

## 7. Производительность и совместимость

- **60 fps:** на `pointermove` при перетаскивании дорожек и ресайзе — только `transform`; коммит модели и полный рендер — на `pointerup`. Никакого `innerHTML` на горячем пути.
- **rem, не px:** все размеры клавиатуры и панелей через `--ui-scale`; нативный `zoom` запрещён (WebKit ломает `getBoundingClientRect`).
- **Падающие полоски не делаем**, в том числе поэтому: это отдельный rAF-конвейер на 60 fps, который сейчас нельзя примешивать к волне.
- **Офлайн:** ни одного сетевого запроса; новый SVG рисуется инлайном; шрифт не расширяем (иконки берём из существующего набора).
- **localStorage ~5 МБ:** разреженные карты + лимит числа дорожек; при переполнении — существующая понятная ошибка сохранения.
- **iPad/Safari:** только ES2020-фичи, уже используемые приложением; аудио через `resumeAudioContext()`; https обязателен для service worker.
- **Темы:** 15 палитр и светлая/тёмная — через семантические CSS-переменные (`--color-surface`, `--color-accent`, …), новых «своих» цветов не вводим.

## 9. Чек-лист ручной приёмки (для владельца)

1. Открыл старую песню — звучит и выглядит как раньше, в микшере одна строка «Гитара».
2. Нажал «+» — появилась «Клавиши» с теми же аккордами; играют обе дорожки.
3. Убавил громкость гитары до нуля — осталось пианино; M/S работают.
4. Кликнул по строке «Клавиши» — в подсказке и карточке «Сейчас» клавиатура, не гриф.
5. Стер аккорд в клавишной дорожке — виден бледный аккорд, но **звука в этом такте нет**.
6. Кликнул по бледной ячейке, выбрал другой аккорд кругом — он зазвучал только в клавишной дорожке.
7. Перетащил «Клавиши» наверх — главная сменилась, бледные подсказки пересчитались, Ctrl+Z вернул порядок.
8. В панели «Аккомпанемент» переключил «Арпеджио ↑» и сменил размер клавиатуры 61 → 88 — звук, закреплённая панель и варианты позиций изменились; ступени в бледных ячейках погасли.
9. Пролистал варианты аппликатуры «‹ 2/5 ›» — контролы не прилипли, Undo работает.
10. Включил свинг — сетка не поехала, рисунок зазвучал триольно.
11. Выгрузил `.struchord`, MIDI и GP5 — открыл, увидел две дорожки, пианино определилось как фортепиано.
12. Обновил страницу на iPad через https — новая версия подтянулась (проверить, что `sw.js` перевыложен парой).
13. В консоли нет ошибок; при игре и перетаскивании интерфейс не подтормаживает.
14. В пустой песне нажал «+» — приложение спросило инструмент, а не создало гитару молча.
15. При активной клавишной дорожке выбрал кругом `C7` — аккорд записался только в неё; в главной гитарной остался прежний.
16. Выгрузил GP5 — клавишная дорожка открылась настоящим станом с нотами, а не табулатурой.

## 10. Риски

| Риск | Почему | Как обходим |
|---|---|---|

## 15. Глоссарий (простыми словами)

- **Дорожка** — один «голос» песни: те же такты, но свои аккорды, инструмент и аккомпанемент.
- **Главная дорожка** — верхняя строка микшера. Её аккорд показывается бледным там, где у другой дорожки аккорда нет.
- **Активная дорожка** — та, которую ты сейчас редактируешь; клик по строке микшера.
- **Зеркало** — старое поле `ev.chord`, которое автоматически повторяет главную дорожку, чтобы старый код не сломался.
- **Призрачный аккорд** — бледная подсказка, **не звучит**.
- **Аппликатура** — картинка, как взять аккорд: гриф у гитары, клавиши у пианино.
- **Голосоведение** — правило, чтобы рука не прыгала: следующий аккорд берётся ближайшими клавишами к предыдущему.
- **Тип аккомпанимента** — рисунок, которым пианино играет аккорд: сразу весь, арпеджио, бас+аккорд и т.д.
- **B-102** — подготовительная работа: научить приложение честно знать, из каких нот состоит любой аккорд.
- **Размер клавиатуры** — сколько клавиш у инструмента (25/37/49/61/76/88); от этого зависит, какие ноты вообще можно сыграть.
- **Нотный стан** — обычные ноты на линейках, в отличие от табулатуры с цифрами ладов.
