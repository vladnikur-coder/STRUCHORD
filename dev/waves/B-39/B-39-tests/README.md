## Применить к актуальной версии приложения

```bash
# 1. Проверка без записи: все ли якоря нашлись
python3 apply_patch.py /путь/к/STRUCHORD.html --check

# 2. Применение (создаётся резервная копия рядом)
python3 apply_patch.py /путь/к/STRUCHORD.html
```

`--check` печатает каждый якорь и число вхождений. Если что-то не так —
скрипт остановится и ничего не испортит; поправь одну строку в `BLOCKS`
или `HOOKS` внутри скрипта.

Откат (проверен: файл становится побайтно равен оригиналу):

```bash
python3 apply_patch.py /путь/к/STRUCHORD.html --uninstall
```

Повторный запуск безопасен: блоки заменяются, а не дублируются.

Части 3, 5 и 6 проверяют реальный DOM (кнопки, панели, строки, «+», «⋯», M/S,
перетаскивание, селекторы). Для этого нужен `jsdom`; если его нет, DOM-тесты
пропускаются, а структурные и модельные проверки всё равно выполняются.

Без аргументов тесты сами соберут ожидаемую версию из `stageN_block.js` /
рабочей папки — удобно для быстрой самопроверки.

Итого: **618 проверок, 0 падений.**

## Почему именно так

Приложение постоянно развивается: актуальный `STRUCHORD.html` отличается от
справочного снимка 0.691 на тысячи строк. Обычный unified diff может не
приложиться, если новый код появился рядом с точкой вставки.

Поэтому `apply_patch.py` ищет уникальные якоря:

- `function getChordNotes(cn, ks) {` — перед ним вставляется блок части 1;
- `const songStore = (function () {` — перед ним вставляется блок части 2;
- `window.songStore = songStore;` — после него вставляется блок части 3;
- `function playChord(c, wrapper) {` — перед ним вставляется блок части 4;
- `function renderFingeringSVG(fingers, bottomPad, opts) {` — перед ним
  вставляется блок части 5;
- `function schedulePatternForEvent(chord, evStart, dur, posCtx, pattern, bpm, ts, square, eventIndex, span, exact, sec) {`
  — перед ним вставляется блок части 6;
- `function gpExportEnsureWriter() {` — перед ним вставляется блок части 7;
- **22 точечных хука:** `sanitizeSongData`, `serializeCurrentSong`,
  `loadSongFromObjectInner`, два шаблона ячеек, `setEventChord`, `strumChord`,
  `scheduleNextEvent`, `playChord`, `stopAllAudio`, `soundChannelInstrument`,
  `PART_SOUNDS.keys`, и четыре вызова `renderFingeringSVG` (тултип,
  две закреплённые карточки, панель «Сейчас» в ленте), а также
  `adoptRhythm` в `schedulePatternForEvent` (общая сетка и свинг для клавишных),
  пять хуков экспорта (`gpExportRun`, `gpExportRunGP5`, `midiExportRun`,
  `gpExportPrepareSong`, `midiExportBuild`).

Проверено на файлах со сдвигом **+2300 строк** и с новым кодом рядом со всеми
десятью якорями: `git apply` во втором случае падает, апплиер — работает, и все
семь наборов тестов проходят на обоих файлах.

Сам `.patch` в корне воркспейса оставлен как запасной вариант для точного
снимка 0.691 и как наглядный diff для ревью.

## Что проверяют тесты

**Часть 1.** 2100 сравнений `getChordNotes` до и после (гитара не изменилась);
~50 аккордов с полным составом; `C11` с терцией, `C13` из 7 тонов, `C7b13`
с квинтой; слэш-бас `C/E`; бемольный стиль; `Cb`/`E#`/`B#`/`Fb`; мусор → `null`.

**Часть 2.** Миграция старого файла в одну гитарную дорожку и пустой
`exportForSave()` (файл не меняется); кругосветка сохранение→загрузка;
отбрасывание битых значений; 6 размеров клавиатуры; «+» копирует аккорды;
пустая ячейка молчит, но призрачная подсказка видна; перетаскивание меняет
главную и переносит аккорды; все мутации через `songStore.dispatch`.

**Часть 3.** Пустая песня без дорожек и её кругосветка; «+» с выбором
инструмента; активная дорожка и призрачный аккорд в ячейках; круг пишет только
в активную; M/S влияют на звук; реальный DOM — кнопка, панель, строки, «⋯»,
громкость, перетаскивание со сменой главной.

**Часть 4.** Синтез пианино (6 парциалов + молоточек) и запасной простой
режим; полный состав `C13`, бас `C/E`, все 6 размеров клавиатуры; свой канал
и громкость на каждую клавишную дорожку; M/S и соло; призрак молчит; стоп
без залипших нот; в звуковом коде нет вызовов `getChordNotes` (R12).

**Часть 5.** Приоритет тонов: при лимите 5 нот `C13` теряет квинту и
ундециму, но сохраняет корень, терцию и септиму; до 5 уникальных вариантов
на всех шести размерах клавиатуры; бас `C/E`; SVG с белыми и чёрными
клавишами, пальцами и корнем; подмена грифа на клавиатуру (обёртка
`renderFingeringSVG`); сохранение выбранного варианта через файл песни
(`v:Cmaj7`); провайдер голосов реально меняет звук; jsdom — кнопка, панель,
размер, тембр, листание «‹ 2/5 ›».

**Часть 6.** Шесть пресетов и их шаги в 3/4, 4/4 и 6/8; наследование «ячейка →
секция → пресет» и сохранение ключа `s:1` в файл песни; ресайз ячейки 1→4 доли
и дробная фаза по сетке квадрата; свинг 2:1 и явное выключение свинга; токены
`H/B/O/A/t3/t5` (минорная терция, `C/E`, полный `C13` без пропусков); звук
реально разносит ноты во времени, призрак молчит, ошибка планировщика не роняет
звук; подсветка шагов совпадает со звуком; jsdom — панель, 6 кнопок, дробность,
свинг, размер клавиатуры, области применения и перехват кнопки «Бой/перебор».

**Часть 7.** Полная кругосветка `.struchord` (дорожки, аккорды, `s:1`, `v:Cmaj7`,
размер клавиатуры, громкость); по партии на дорожку, GM 0/25, `viewMode: staff`;
призрак, M/S; виртуальный строй C2…C8 (для всех высот 36…108 «строй+лад = MIDI»);
**реальный GPIF-писатель** (XML с `<Octave>`/`<Tone>`, без `<String>`/`<Fret>`);
**реальный GP5-писатель** (заголовок v5.10, ноты записаны, нет потери «вне грифа»);
**реальный MIDI-писатель** (`MThd`, format 1, 3 трека, program 0, note-on 60/64,
CC7=89, note-off); **bump_release.py** (0.691→0.692, `struchord-v691→v692`,
sha256 совпадает с фактом, резервная копия, повторный запуск 0.692→0.693).

## После применения

1. Прогнать полный корпус тестов проекта (131 набор). Ожидания менять не нужно.
2. Добавить в `README.md` три абзаца про инструментную конвенцию, токены
   шагов и экспорт дорожек (R12) — готовый текст в `../PATCH-NOTES.md`.
3. **R7 + R6, одной командой:**
   `python3 bump_release.py ../STRUCHORD.html ../sw.js ../ROADMAP.md --wave "B-39 · Режим «Клавиши»"`
   (сначала можно с `--dry-run`). Скрипт поднимет видимую версию, `CACHE_NAME`
   в `sw.js`, посчитает sha256/размер и вставит строку в реестр релизов.
   HTML и `sw.js` выкладывать **парой**.
4. Коммит только в ветку текущей Arena-сессии (R9).

Подробности — в `../PATCH-NOTES.md`, архитектура — в `../plan-keys-mode.md`.
